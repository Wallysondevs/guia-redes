DevTools (F12): ver a rede no navegador

Você não precisa de terminal para ver a rede acontecendo: o próprio navegador tem uma central de controle escondida. Aperte F12 (ou Ctrl+Shift+I no Windows/Linux, Cmd+Opt+I no Mac), vá na aba Network (Rede) e recarregue a página: cada pedido que o site faz aparece na lista, com status, tamanho e tempo.

Você vai aprender
  • Abrir o DevTools: F12 ou clique direito → "Inspecionar".
  • A aba Network: a lista de requisições da página (documento, CSS, JS, imagens, XHR/Fetch = chamadas de API).
  • As colunas: Name, Status (200, 404…), Type, Size e Time — e o gráfico de tempo (waterfall).
  • Clicar numa requisição: abas Headers (cabeçalhos do pedido e da resposta), Preview, Response e Timing.
  • O equivalente na linha de comando: curl -i — mesma informação, modo texto.

O DevTools abre encaixado embaixo (ou do lado). Clique na aba Network (em português, às vezes aparece como "Rede").

A aba Network: cada pedido da página

Com a aba Network aberta, recarregue a página (F5) — e observe: a página não é um pedido só. Abrir um site dispara dezenas de requisições:

  • O documento HTML principal (filter Doc);
  • CSS, JavaScript, fontes e imagens (CSS, JS, Img);
  • Chamadas de API que buscan dados em JSON (Fetch/XHR);
  • WS = WebSockets (conexão contínua, ex.: chat).

Cada linha da lista mostra: Name (a URL pedida), Status (200 verde, 404 vermelho…), Type (document, xhr, png…), Size (quanto transferiu) e Time (quanto demorou). Embaixo, o waterfall desenha quanto tempo cada pedido levou, um do lado do outro.

Clicando numa requisição

Clique em qualquer linha da lista para abrir o detalhe dela:

Headers
Os cabeçalhos: em cima, a resposta (status 200, content-type, server…); embaixo, o pedido (GET, Host, User-Agent, Cookie…). É a mesma conversa que o curl -i mostra.
Preview / Response
A resposta "bonitinha" (JSON formatado, imagem renderizada) ou o texto puro.
Timing
O detalhamento do tempo: quanto esperou o DNS, conectou, enviou o pedido e esperou a resposta (TTFB).

É assim que se descobre "por que o site está lento": abre o Network, recarrega e olha qual requisição demorou mais ou deu erro.

O mesmo no terminal: curl -i

Tudo o que a aba Network mostra, o curl -i mostra em texto — por isso os dois andam juntos. Exemplo: chamar a API fictícia e ver o cabeçalho dizendo que a resposta é JSON:

$ curl -i https://api.exemplo.com/usuarios
HTTP/2 200
content-type: application/json
content-length: 87

[{"id":1,"nome":"Ana"},{"id":2,"nome":"Beto"},{"id":3,"nome":"Carla"}]

Na aba Network, essa mesma chamada apareceria como uma linha usuarios do tipo fetch, status 200, e na aba Preview o JSON bonitinho.

Missão: digite curl -i https://api.exemplo.com/usuarios e aperte Enter. Nos cabeçalhos da resposta, procure content-type: application/json — é a API dizendo "o que eu te mandei são dados, não página". No navegador, abra o F12 → Network e ache uma requisição assim no seu site favorito.

Resumo

  • F12 abre o DevTools; a aba Network lista todas as requisições que a página faz ao recarregar.
  • Colunas: Name, Status (200/404…), Type, Size, Time + o gráfico waterfall de tempos.
  • Clicando na requisição: Headers (pedido e resposta), Preview/Response (o conteúdo) e Timing (onde o tempo foi gasto).
  • Na linha de comando, o equivalente é o curl -i — mesma conversa em texto.
