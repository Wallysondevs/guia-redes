Comandos de rede (cola)

Esta é a sua cola de consulta rápida: os comandos de rede que você mais vai usar no terminal, separados por categoria, com sintaxe, exemplo prático e o que cada um faz. Não decore — guarde esta página nos favoritos. A regra de bolso da Ana quando trava: ping (responde?), dig (resolve?), curl (o serviço HTTP responde?), ss (a porta está aberta aqui?).

Você vai aprender
  • Os comandos de diagnóstico: ping, traceroute, dig, nslookup, curl, wget, nc, telnet, nmap, tcpdump, whois.
  • Os de configuração e consulta local: ip, ifconfig, ss, netstat, route, arp, hostname, cat /etc/hosts, cat /etc/resolv.conf, ssh.
  • O fluxo de diagnóstico na ordem certa (a seção abaixo).
  • Referências cruzadas: portas comuns, status HTTP, headers, registros DNS, problemas comuns.

O fluxo de diagnóstico (use nesta ordem)

$ ping exemplo.com            « 1. a máquina responde? (ICMP passa)
$ dig exemplo.com +short      « 2. o nome resolve para um IP?
$ curl -i https://exemplo.com « 3. o serviço HTTP responde? qual status?
$ traceroute exemplo.com      « 4. onde o caminho para no meio?
$ ss -tlnp                    « 5. e aqui na minha máquina, as portas estão abertas?

Se o passo 1 falha mas o 2 funciona, o problema é ICMP bloqueado (firewall) — não necessariamente a máquina está fora. Se o 2 falha, é DNS (veja problemas comuns).

Diagnóstico de conectividade

SintaxeExemploO que faz / saída típica
ping [-c N] HOSTping -c 4 exemplo.comEnvia pacotes ICMP e mede resposta. Linhas 64 bytes from …: icmp_seq=1 ttl=64 time=23.4 ms = resposta chegando; resumo final com % packet loss. -c 4 limita a 4 pacotes.
traceroute HOSTtraceroute google.comMostra cada "salto" (roteador) até o destino, com 3 tempos em ms por salto. Serve para achar onde a rota quebra. Equivalente moderno: tracepath.
curl [OPÇÕES] URLcurl -i https://exemplo.comFaz uma requisição HTTP e imprime a resposta. -i inclui headers (1ª linha = status, ex.: HTTP/1.1 200 OK); -v mostra a conversa; -X POST -d '{}' envia dados. Erros comuns: (6) Could not resolve host, (7) Connection refused.
wget URLwget http://exemplo.com/arquivo.zipBaixa um arquivo pela rede e salva no disco (mostra progresso e 200 OK). Bom para downloads em servidor, sem interface gráfica.
nc -zv HOST PORTAnc -zv localhost 8000Testa se uma porta TCP abre, sem mandar dados: imprime Connection to … port [tcp/*] succeeded! ou refused/timed out.
telnet HOST PORTAtelnet exemplo.com 80Versão antiga do nc: abre uma conexão TCP "crua" (dá para digitar comandos HTTP na mão). Connected to … = porta aberta. Não use para senhas — vai em texto puro.
nmap [OPÇÕES] HOSTnmap localhost / nmap -p 80,443 exemplo.comEscaneia portas do host e lista as abertas com o serviço (ex.: 22/tcp open ssh). Use só em máquinas suas (aula scan ético).
tcpdump -i IFACE [filtro]sudo tcpdump -i eth0 port 53Captura os pacotes que passam pela interface em tempo real (cada linha = 1 pacote, com IPs e portas). Filtros: host X, port N, tcp/udp. Ctrl+C para. Aula tcpdump.

DNS

SintaxeExemploO que faz / saída típica
dig HOST [TIPO] [+short|+trace]dig exemplo.com +shortConsulta DNS completa. +short imprime só o IP (93.184.216.34); MX, TXT, NS pedem tipos específicos (veja registros DNS); +trace segue a delegação desde a raiz. Domínio inexistente → status: NXDOMAIN.
dig @SERVIDOR HOSTdig @8.8.8.8 exemplo.comConsulta um servidor DNS específico (burla o padrão do sistema — ótimo para testar se o problema é o DNS local).
nslookup HOSTnslookup exemplo.comVersão simples do dig: mostra Server: usado e Non-authoritative answer: Name / Address. Falha → ** server can't find …: NXDOMAIN.
whois DOMÍNIOwhois exemplo.comConsulta o registro do domínio (quem registrou, datas, servidores de nome).

SintaxeExemploO que faz / saída típica
