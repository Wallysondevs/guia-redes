Comando ping a fundo

Você já pingou na aula anterior — agora vamos abrir o comando: a anatomia, as opções úteis, como ler as estatísticas e os erros que ele mostra. No fim, você aprende a ordem clássica de diagnóstico com ping: do mais perto (sua máquina) até a internet.

Você vai aprender
  • A anatomia: ping [-c N] HOST — o que cada peça faz.
  • Pingar por IP direto (pula o DNS) e por nome (passa pelo DNS).
  • Ler as estatísticas: transmitidos, recebidos, perda % e tempo total.
  • O erro real cannot resolve: o DNS não achou o nome.
  • A ordem de diagnóstico: 127.0.0.1 → IP da máquina → gateway → internet.

Anatomia do comando

ping
O programa: manda pacotes ICMP echo ("alô") e ouve a resposta.
-c 3
count: manda só 3 pacotes e para (o padrão no simulador é 4; no Linux real é infinito até Ctrl+C).
exemplo.com
O destino: pode ser um nome (o DNS traduz na hora) ou um IP direto.
$ ping -c 3 exemplo.com
PING exemplo.com (93.184.216.34) 56(84) bytes of data.
64 bytes from 93.184.216.34: icmp_seq=1 ttl=64 time=23.4 ms
64 bytes from 93.184.216.34: icmp_seq=2 ttl=64 time=22.9 ms
64 bytes from 93.184.216.34: icmp_seq=3 ttl=64 time=23.7 ms

--- exemplo.com ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2002ms

Missão: digite ping -c 3 exemplo.com e aperte Enter. Devem voltar exatamente 3 linhas 64 bytes from … e o resumo deve dizer 3 packets transmitted, 3 received.

Nome ou IP? A diferença passa pelo DNS

Compare: pingar o nome exige que o DNS traduza primeiro (e pode falhar no nome); pingar o IP vai direto:

$ ping exemplo.com
PING exemplo.com (93.184.216.34) 56(84) bytes of data.
64 bytes from 93.184.216.34: icmp_seq=1 ttl=64 time=23.4 ms …
$ ping 93.184.216.34
PING 93.184.216.34 (93.184.216.34) 56(84) bytes of data.
64 bytes from 93.184.216.34: icmp_seq=1 ttl=64 time=23.1 ms …

Útil para diagnosticar: se ping exemplo.com falha com erro de nome mas ping 93.184.216.34 responde, o problema é o DNS, não a rede.

Erro real: nome que não existe

cannot resolve 
$ ping site-que-nao-existe.com
ping: cannot resolve site-que-nao-existe.com: Name or service not known

O ping nem chegou a mandar pacote: o DNS disse que esse nome não existe (NXDOMAIN). Nome errado = esse erro. Confira a escrita ou teste com dig site-que-nao-existe.com.

Missão: digite ping site-que-nao-existe.com e aperte Enter. Veja o erro cannot resolve — o DNS não achou esse nome.

Lendo as estatísticas

  • 4 packets transmitted, 4 received — quantos saíram e quantos voltaram.
  • 0% packet loss — a perda de pacotes. Perto de 100% = o destino não está respondendo (ou bloqueia ICMP).
  • time 3000ms — o tempo total do teste (1 segundo entre cada pacote).

A ordem clássica de diagnóstico com ping

Quando "a internet não funciona", pingue nessa ordem — cada etapa elimina uma suspeita:

OrdemComandoSe falhar, o problema é…
1ping 127.0.0.1A própria máquina (rede interna quebrada)
2ping 192.168.1.50Sua placa de rede / cabo / Wi-Fi
3ping 192.168.1.1A conexão com o roteador (sua rede local)
4ping 8.8.8.8A saída para a internet (roteador ou provedor)
5ping exemplo.comSomente o DNS (a rede está ok, o nome não resolve)

Resumo

  • ping [-c N] HOST: manda N pacotes de teste e mede resposta e tempo. Nome passa pelo DNS; IP vai direto.
  • Estatísticas: transmitidos/recebidos, % packet loss e tempo total.
  • Erro cannot resolve … Name or service not known = o DNS não achou o nome.
  • Diagnóstico em escada: 127.0.0.1 → seu IP → gateway → 8.8.8.8 → nome na internet.
