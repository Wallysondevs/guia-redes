Seção de projetos — mão na massa

Chegou a hora de juntar as peças. Até aqui você aprendeu o que é IP, porta, DNS, HTTP e viu os comandos um a um. Agora a Ana vai fazer cinco projetos de verdade, do tipo que se faz no dia a dia de quem trabalha com rede: subir um site local, consumir uma API, apelidar um endereço no DNS local, ligar duas máquinas numa rede virtual e vigiar as portas abertas do computador.

Você vai aprender
  • A servir um site estático local com python3 -m http.server 8000 e acessar com curl localhost:8000.
  • A testar uma API pública na prática: dig para achar o IP e curl -i para ler status e JSON.
  • A usar o /etc/hosts como "agenda de apelidos" local de DNS.
  • A criar uma rede interna entre duas VMs (VirtualBox) e pingar uma na outra.
  • A monitorar portas abertas com ss -tlnp, nc e um script com watch.

Como funcionam os projetos

Cada projeto é um passo a passo curto, com os comandos reais e a saída que eles imprimem. Nas caixas escuras dá para experimentar no terminal simulado da máquina fictícia ana@notebook (IP 192.168.1.50/24, gateway 192.168.1.1, DNS 192.168.1.1 e 8.8.8.8): cada caixa tem uma missão — digite o comando pedido e, quando a saída certa aparecer, gagne o ✔ "Missão cumprida!". Se travar, clique em Ver comando.

Quer fazer na sua máquina de verdade? Os mesmos comandos funcionam no Linux/macOS (no Windows, use o WSL ou o Prompt com curl, que já vem instalado). Só o python3 -m http.server e o /etc/hosts são de máquina Linux — no Windows o hosts fica em C:\Windows\System32\drivers\etc\hosts.

Missão: antes de começar, digite help no terminal abaixo e veja a lista de comandos de rede que o simulador entende.

Os cinco projetos

ProjetoO que você fazComandos que pratica
1. Site localCria uma pasta com um index.html, sobe um servidor HTTP na porta 8000 e acessa com o navegador e com curl.python3 -m http.server 8000, curl -i localhost:8000, ss -tlnp
2. API públicaDescobre o IP de api.exemplo.com com DNS e consome a API: lista usuários, vê um 404 de verdade.dig api.exemplo.com +short, curl -i https://api.exemplo.com/usuarios
3. DNS local (/etc/hosts)Adiciona um apelido local (meusite.local → 192.168.1.60) e confirma com dig e ping.cat /etc/hosts, dig meusite.local +short, cat /etc/resolv.conf
4. Rede virtual entre 2 VMsNo VirtualBox, cria uma "rede interna" e liga duas VMs nela; uma pinga a outra e acessa por SSH.ping 192.168.1.60, ssh ana@192.168.1.60, ip addr
5. Monitorar portasLista as portas abertas do notebook, testa uma porta com nc e monta um monitor ao vivo com watch.ss -tlnp, netstat -tlnp, nc -zv localhost 8000, nmap localhost

Pré-requisitos

  • Ter passado pelo Nível 1: introdução, IP, portas, DNS, HTTP e os comandos ping, curl, dig e ss.
  • Entender a máquina fictícia: ana@notebook, rede 192.168.1.0/24 — confirme com ip addr e ip route no terminal abaixo.
  • Se quiser repetir na máquina real, um Linux com python3, curl e iproute2 (o pacote do comando ss/ip) installed.

Missão: confirme a sua máquina no simulador: rode ip addr e ache o IP 192.168.1.50/24 na interface eth0. Depois rode ip route para ver o gateway.

$ ip addr

    inet 127.0.0.1/8 scope host lo
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 state UP
    link/ether aa:bb:cc:dd:ee:ff
    inet 192.168.1.50/24 scope global eth0
$ ip route

192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.50
Regra de bolso dos projetos: todo projeto de rede segue o mesmo roteiro de diagnóstico — ping (a máquina responde?), dig (o nome resolve?), curl (o serviço responde?), ss (a porta está aberta aqui?). Se travar em algum passo, volte por esse roteiro. A página Problemas comuns detalha cada falha.
