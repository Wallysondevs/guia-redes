Comando dig / nslookup: perguntar ao DNS

O dig (Domain Information Groper) é a ferramenta de linha de comando para perguntar direto a um servidor DNS — como ligar para a telefonista em vez de olhar a agenda. Nesta aula: a anatomia do comando, a saída completa, o +short para scripts, o +trace que mostra a hierarquia, os tipos de registro e o erro NXDOMAIN.

Você vai aprender
  • A anatomia: dig [@servidor] HOST [TIPO] [+opção].
  • Ler a saída completa: HEADER (status NOERROR/NXDOMAIN), QUESTION, ANSWER e SERVER (quem respondeu).
  • +short: só a resposta (o IP) — perfeito para scripts.
  • +trace: segue a hierarquia raiz → TLD → autoritativo.
  • Tipos de registro: A (IPv4), AAAA (IPv6), MX (e-mail), NS, CNAME…
  • nslookup: a alternativa mais simples, e /etc/resolv.conf (quem é o DNS padrão da máquina).

Anatomia do comando

dig
O programa: consulta servidores DNS e mostra a resposta completa.
@8.8.8.8
Opcional: pergunta a qual servidor DNS (sem @, usa o padrão do sistema, 192.168.1.1).
exemplo.com
O nome que você quer traduzir.
A
O tipo de registro: A = endereço IPv4 (o padrão). Outros: AAAA, MX, NS, TXT…
+short
Opção de saída: imprime só a resposta, sem enfeite.

A saída completa

$ dig exemplo.com
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 4821
;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1

;; QUESTION SECTION:
;exemplo.com.			IN	A

;; ANSWER SECTION:
exemplo.com.		3600	IN	A	93.184.216.34

;; Query time: 12 msec
;; SERVER: 192.168.1.1#53(192.168.1.1)
;; MSG SIZE  rcvd: 64
  • status: NOERROR + ANSWER: 1 — a consulta deu certo e veio 1 resposta.
  • ANSWER SECTION — a resposta de verdade: exemplo.com. 3600 IN A 93.184.216.34 (nome, TTL em segundos, tipo A, IP).
  • SERVER: 192.168.1.1#53 — quem respondeu (o DNS da rede local, na porta 53).
  • Query time: 12 msec — quanto tempo a consulta levou.

+short: só o IP (para scripts)

$ dig exemplo.com +short
93.184.216.34
$ dig google.com +short
142.250.72.142
$ dig api.exemplo.com +short
93.184.216.35

Missão: digite dig exemplo.com +short e aperte Enter. A saída deve ser só o IP 93.184.216.34.

+trace: ver a hierarquia DNS funcionando

Com +trace, o dig começa pela raiz e vai descendo até o servidor autoritativo do domínio — mostra a agenda em camadas:

$ dig exemplo.com +trace
; <<>> DiG 9.18 <<>> +trace exemplo.com
.                       518400  IN  NS  a.root-servers.net.
;; Received 239 bytes from 192.168.1.1#53(192.168.1.1) in 4 ms

com.                    172800  IN  NS  a.gtld-servers.net.

exemplo.com.            86400   IN  NS  ns1.exemplo.com.

exemplo.com.            3600    IN  A   93.184.216.34
;; Query time: 38 msec
;; SERVER: 8.8.8.8#53(8.8.8.8)

Erro real: NXDOMAIN (nome não existe)

status: NXDOMAIN 
$ dig site-que-nao-existe.com
;; ->>HEADER<<- opcode: QUERY, status: NXDOMAIN, id: 7712
;; QUESTION SECTION:
;site-que-nao-existe.com.	IN	A

;; Query time: 12 msec
;; SERVER: 192.168.1.1#53(192.168.1.1)

NXDOMAIN = Non-Existent Domain: a agenda telefônica disse que esse nome não está cadastrado. E se o servidor DNS estiver fora do ar, o erro é connection timed out; no servers could be reached.

nslookup: a consulta simples

O nslookup faz a mesma pergunta com saída mais curtinha — bom para um teste rápido:

$ nslookup google.com
Server:		192.168.1.1
Address:	192.168.1.1#53

Non-authoritative answer:
Name:	google.com
Address: 142.250.72.142

Missão: digite nslookup google.com e aperte Enter. Na resposta Non-authoritative answer, o número deve ser 142.250.72.142.

Resumo

  • dig [@servidor] HOST [TIPO] [+opção] — pergunta a um DNS e mostra tudo; +short mostra só o IP.
  • Saída completa: HEADER (status), QUESTION, ANSWER (o IP), SERVER (quem respondeu) e Query time.
  • +trace mostra a hierarquia: raiz (.) → TLD (.com) → autoritativo (ns1.exemplo.com).
  • nslookup HOST é a versão simples; o DNS padrão da máquina está em /etc/resolv.conf.
  • Nome inexistente = NXDOMAIN; servidor fora do ar = connection timed out.
