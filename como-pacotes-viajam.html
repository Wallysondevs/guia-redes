Como o pacote viaja: traceroute passo a passo

Quando o notebook da Ana acessa exemplo.com, o pacote não vai numa linha reta: ele passa por vários roteadores — o de casa, os do provedor, os de backbone — até chegar ao servidor. Cada roteador é um salto (hop). O traceroute é a ferramenta que revela esse caminho. A analogia: é como mandar uma carta com um prazo de validade (TTL) que cada posto dos correios carimba e decrementa; quando o prazo zera, o posto manda um aviso de volta dizendo "eu sou o posto X e o prazo acabou". O traceroute manda cartas com prazo 1, 2, 3… e anota quem respondeu em cada etapa.

Você vai aprender
  • Como o traceroute usa o campo TTL do pacote + respostas ICMP "time exceeded".
  • A ler cada linha: número do salto, IP do roteador e os 3 tempos de ida e volta.
  • Quem é o 1º salto (sempre o seu gateway 192.168.1.1) e os últimos (a rede do destino).
  • O que significam os * * * (firewall que não responde — não é rede caída).

O truque do TTL

Todo pacote IP tem um campo TTL (Time To Live) — um contador que cada roteador decrementa em 1. Se o TTL chega a zero, o roteador descarta o pacote e manda um aviso ICMP "time exceeded" de volta para a origem. O TTL existe para o pacote não ficar circulando para sempre numa rota com erro (loop).

O traceroute explora isso: ele manda 3 sondas com TTL=1 (o 1º roteador responde "excedido" e se revela), depois 3 com TTL=2 (o 2º roteador responde), depois TTL=3… até o destino responder de verdade. Juntando as respostas, ele monta o mapa do caminho.

O que significam os * * *

Se um salto aparece como * * *, aquele roteador não respondeu o ICMP "time exceeded" — normalmente porque um firewall bloqueia essas respostas. Não significa que a rede caiu: se os saltos seguintes aparecem, o pacote continuou passando por ali normalmente. Muitos roteadores simplesmente não respondem traceroute para não se denunciar.

Resumo

  • O pacote até um destino passa por vários roteadores (saltos); o 1º é sempre o seu gateway.
  • O traceroute manda sondas com TTL 1, 2, 3…; cada roteador que esgota o TTL responde "time exceeded" e se revela.
  • Cada linha mostra o IP do salto e 3 tempos de ida e volta; * * * = roteador que não respondeu (firewall), não necessariamente problema.
  • Use para diagnosticar "onde a conexão para": se trava no salto 2, o problema está no provedor; se no 1, na sua rede local.
