Headers HTTP comuns (cola)

Uma conversa HTTP é feita de headers (cabeçalhos) + corpo. Pense nos headers como o envelope de uma carta: diz quem envia, quem recebe, o que tem dentro e como tratar — o corpo (a carta em si) vem depois de uma linha em branco. No pedido, os headers vão prefixados de >; na resposta, de < (veja com curl -v).

Você vai aprender
  • Os headers de requisição que você mais usa: Host, User-Agent, Accept, Content-Type, Authorization, Cookie.
  • Os headers de resposta mais comuns: Content-Type, Content-Length, Server, Set-Cookie, Location, Cache-Control, ETag, Strict-Transport-Security.
  • Como ler tudo isso na prática: curl -i (resposta) e curl -v (ida e volta).

Uma conversa real, lado a lado

$ curl -v https://exemplo.com
* Trying 93.184.216.34:443...
* Connected to exemplo.com (93.184.216.34) port 443
> GET / HTTP/1.1            « linha de pedido: método + caminho + versão
> Host: exemplo.com         « header de requisição
> User-Agent: curl/8.5.0
> Accept: */*
>
< HTTP/2 200               « linha de status da resposta
< server: nginx/1.25.3
< content-type: text/html; charset=UTF-8
< strict-transport-security: max-age=31536000
<
<html>…</html>             « corpo (a página em si)

Headers de requisição (quem pede)

HeaderExemploPara que serve
HostHost: api.exemplo.comDiz qual site dentro do servidor (um mesmo IP pode hospedar vários sites — é o "nome no interfone"). Obrigatório.
User-AgentUser-Agent: curl/8.5.0Identifica quem está pedindo (navegador, app, script).
AcceptAccept: application/jsonDiz o que o cliente aceita receber (HTML, JSON, imagens…). */* = qualquer coisa.
Content-TypeContent-Type: application/jsonDiz o formato do corpo enviado (JSON, formulário, arquivo…).
Content-LengthContent-Length: 15Tamanho do corpo em bytes (o servidor usa para saber onde o corpo acaba).
AuthorizationAuthorization: Bearer eyJ…Leva o token/senha da autenticação (API).
CookieCookie: sessao=abc123Leva os cookies da sessão de volta ao servidor (aula cookies e sessões).
RefererReferer: https://google.com/…De qual página o pedido veio.

Headers de resposta (quem atende)

HeaderExemploPara que serve
Content-TypeContent-Type: text/html; charset=UTF-8Formato do corpo que veio (HTML, JSON, imagem…). O navegador usa para decidir como exibir.
Content-LengthContent-Length: 1256Tamanho do corpo em bytes.
ServerServer: nginx/1.25.3Qual software atendeu (informativo — nem sempre diz a verdade de propósito).
Set-CookieSet-Cookie: sessao=abc; HttpOnly; Path=/O servidor manda um cookie novo para o navegador guardar.
LocationLocation: https://exemplo.com/novoPara onde seguir num redirecionamento 3xx.
Cache-ControlCache-Control: max-age=3600Quanto tempo o navegador pode guardar a resposta em cache (sem pedir de novo).
ETagETag: "a1b2c3"Uma "impressão digital" do arquivo: se não mudou, o servidor responde 304 em vez de mandar tudo de novo.
Strict-Transport-SecurityStrict-Transport-Security: max-age=31536000"Daqui para frente, só fale comigo por HTTPS" (obrigatório em sites HTTPS bons).
Access-Control-Allow-OriginAccess-Control-Allow-Origin: *CORS: quais sites podem chamar essa API pelo navegador.

Na prática: curl -i mostra os headers da resposta

$ curl -i http://exemplo.com
HTTP/1.1 200 OK
Server: nginx/1.25.3
Content-Type: text/html; charset=UTF-8
Content-Length: 1256
Connection: keep-alive

<html>…</html>

Missão: rode curl -i http://exemplo.com e ache o header Server: na resposta (diz quem atendeu).

Missão: rode curl -i https://api.exemplo.com/usuarios e veja o header content-type: application/json — a resposta é dados, não página.

Resumo

  • HTTP = linha inicial + headers + linha em branco + corpo. Headers são o "envelope"; o corpo é a "carta".
  • Requisição leva Host (obrigatório), Accept, Authorization, Cookie…; resposta traz Content-Type, Set-Cookie, Location, Cache-Control…
  • Veja resposta com curl -i URL; a conversa inteira com curl -v URL.
