NAT: vários PCs, um IP público

Pense numa empresa: ela tem um único número de telefone público na fachada, mas cada funcionário tem um ramal interno (101, 102, 103…). Quem liga de fora fala só com o número público; o porteiro anota "a ligação entrou pelo ramal 102" e, quando a resposta chega, entrega para o ramal certo. O NAT (Network Address Translation) é exatamente esse porteiro: ele deixa vários computadores de IPs privados saírem para a internet usando um único IP público.

Você vai aprender
  • O que o NAT troca nos pacotes: IP de origem privado → IP público do roteador.
  • A tabela de tradução e a sobrecarga de portas (PAT/NAPT) — como ele sabe de quem era a resposta.
  • Os tipos de NAT: estático (1:1), dinâmico (pool) e por portas (o mais comum em casa).
  • Por que o NAT existe: o IPv4 tem só ~4,3 bilhões de endereços.
  • O que é port forwarding (abrir uma porta para um servidor interno).

O passo a passo de um pacote com NAT

Na rede da Ana, o notebook (192.168.1.50) abre exemplo.com (93.184.216.34). O roteador (192.168.1.1, que tem o IP público 200.100.50.10 na internet) faz a tradução:

Saída (dentro da rede)
Origem: 192.168.1.50:54321 → Destino: 93.184.216.34:80. O pacote vai até o roteador (é o gateway padrão).
NAT no roteador
O roteador troca a origem para 200.100.50.10:40123 e anota na tabela: "192.168.1.50:54321 corresponde a 200.100.50.10:40123".
Saída (na internet)
Origem: 200.100.50.10:40123 → Destino: 93.184.216.34:80. Para o servidor, quem pediu a página foi o IP público.
Resposta
O servidor responde para 200.100.50.10:40123; o roteador consulta a tabela e reescreve o destino para 192.168.1.50:54321 e entrega ao notebook.
Dentro da rede (antes do NAT)Na internet (depois do NAT)
192.168.1.50:54321 → 93.184.216.34:80200.100.50.10:40123 → 93.184.216.34:80
192.168.1.60:51000 → 142.250.72.142:443200.100.50.10:40124 → 142.250.72.142:443

Como dá para ter vários computadores usando o mesmo IP público ao mesmo tempo? Graças às portas: cada conexão nova ganha uma porta pública diferente (40123, 40124…). Esse truque se chama PAT (Port Address Translation), ou NAT com sobrecarga — o tipo que todo roteador doméstico usa.

Tipos de NAT

TipoComo funcionaExemplo
Estático (1:1)Um IP privado equivale sempre ao mesmo IP públicoServidor interno que precisa de IP público fixo
Dinâmico (pool)O roteador tira IPs públicos de um conjunto (pool) e empresta conforme a demandaProvedor entrega um bloco de IPs para vários clientes
PAT / NAPT (sobrecarga de portas)Muitos privados saem pelo mesmo IP público, diferenciados pela portaTodo roteador Wi-Fi doméstico — a sua casa inteira sai pelo mesmo IP

Por que o NAT foi inventado

O IPv4 tem 2³² = ~4,3 bilhões de endereços — e a internet já tem muito mais dispositivos que isso (celulares, TVs, geladeiras…). Como não dá para dar um IP público para cada um, o NAT permite que bilhões de IPs privados (192.168.x.x, 10.x.x.x — lembra?) compartilhem poucos IPs públicos. Sem NAT, os endereços IPv4 teriam acabado bem antes.

Veja na máquina da Ana

O notebook dela tem IP privado; a conversa com a internet acontece "por trás" do roteador com NAT:

$ curl -i http://exemplo.com
HTTP/1.1 200 OK
Server: nginx/1.25.3
Content-Type: text/html; charset=UTF-8
Content-Length: 1256
Connection: keep-alive

Para o servidor do exemplo.com, quem fez essa requisição foi o IP público do roteador da Ana — o servidor nem desconfia que existe um 192.168.1.50 por trás. E o primeiro salto de qualquer rota para fora é sempre o roteador:

$ traceroute exemplo.com
traceroute to exemplo.com (93.184.216.34), 30 hops max, 60 byte packets
 1  192.168.1.1         2.431 ms  3.105 ms  2.887 ms   « o roteador com NAT: 1º salto

Missão: rode curl -i http://exemplo.com e veja o HTTP/1.1 200 OK chegando — do ponto de vista do servidor, veio do IP público do roteador (NAT), não do 192.168.1.50.

Missão: rode traceroute exemplo.com e repare que o primeiro salto é sempre o 192.168.1.1 — é ele quem faz o NAT e manda o pacote para a internet.

NAT não é firewall — e "meu IP" é o do roteador

O NAT esconde os IPs internos, mas não bloqueia portas por conta própria; a proteção vem do firewall (que geralmente anda junto no roteador). E quando você entra num site de "qual é o meu IP", o endereço mostrado é o público do roteador (200.100.50.10), não o 192.168.1.50 do notebook. Para expor um servidor interno na internet, configura-se o port forwarding no roteador: "pacotes na porta pública 8080 vão para o 192.168.1.60:80".

Resumo

  • NAT troca o IP de origem privado pelo IP público do roteador na saída, e faz o caminho inverso na resposta.
  • PAT (sobrecarga de portas) permite muitos privados no mesmo IP público, diferenciados pela porta de origem.
  • Tipos: estático (1:1), dinâmico (pool) e PAT (o de casa).
  • O NAT economiza IPs públicos — essencial num mundo com mais dispositivos que endereços IPv4.
  • Quem faz NAT em casa é o roteador (gateway 192.168.1.1) — primeiro salto do traceroute.
