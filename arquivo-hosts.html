/etc/hosts — o DNS de rascunho da sua máquina

Antes de telefonar para a agenda geral (o DNS da internet, aula DNS a fundo), você olha os rabiscos da sua própria agenda. O arquivo /etc/hosts faz exatamente isso no computador: ele mapeia nome → IP localmente, e essa tabela tem prioridade sobre o DNS.

Você vai aprender
  • O formato do arquivo: IP nome apelido-opcional, um por linha.
  • A ver o arquivo da máquina da Ana: cat /etc/hosts.
  • Que o ping roteador funciona por causa do hosts — e não do DNS.
  • Para que serve: testar sites locais, dar apelidos à rede, bloquear sites.
  • Os cuidados: precisa de administrador e vale só na sua máquina.

O arquivo na máquina da Ana

$ cat /etc/hosts
127.0.0.1   localhost
127.0.1.1   notebook
192.168.1.50 notebook
192.168.1.1  roteador gateway
# formato de cada linha:
# IP          nome-principal   apelido-opcional
192.168.1.1  roteador         gateway
192.168.1.1
O IP para o qual o nome vai apontar.
roteador
O nome principal — é como você vai chamar essa máquina.
gateway
Um apelido (alias) — também funciona, na mesma linha.

Regras: um registro por linha; comentários começam com #; o primeiro nome depois do IP é o principal, os demais são apelidos.

Missão: abra o "DNS local" da máquina da Ana e ache o apelido do roteador: cat /etc/hosts

Funciona na hora: o hosts passa na frente do DNS

Repare na diferença entre as duas linhas abaixo — mesma sintaxe de ping, mas a resposta veio de lugares diferentes:

$ ping roteador
PING roteador (192.168.1.1) 56(84) bytes of data.
64 bytes from 192.168.1.1: icmp_seq=1 ttl=64 time=1.32 ms
64 bytes from 192.168.1.1: icmp_seq=2 ttl=64 time=1.28 ms

--- roteador ping statistics ---
2 packets transmitted, 2 received, 0% packet loss
$ ping meusite.local
PING meusite.local (192.168.1.60) 56(84) bytes of data.
64 bytes from 192.168.1.60: icmp_seq=1 ttl=64 time=2.10 ms
  • roteador → 192.168.1.1 veio do /etc/hosts (a linha que vimos acima).
  • meusite.local → 192.168.1.60 veio do DNS (não está no hosts).

A ordem é sempre: primeiro o /etc/hosts, depois o DNS. Se um nome existe nos dois, vale o do hosts.

Missão: prove que o hosts funciona: pingue o apelido do roteador: ping roteador — o IP 192.168.1.1 veio do /etc/hosts

Missão: agora um nome que não está no hosts e vem do DNS: ping meusite.local

Para que serve na prática

  • Testar um site antes de publicar: aponte o domínio real para 127.0.0.1 (sua máquina) ou para o IP do servidor de teste — só no seu computador.
  • Dar apelidos às máquinas da rede local: roteador, impressora, nas… sem depender do DNS.
  • Bloquear um site: aponte o domínio para 127.0.0.1 e ele "não abre" (na prática, para controle de verdade usa-se DNS filtrado ou firewall).
Cuidados: editar o /etc/hosts exige administrador (sudo) e vale só na sua máquina — não adianta editar no notebook achando que vai "consertar" o celular. E se você apontar um site real para outro IP, ele "quebra" só para você: remova a linha depois do teste.

De onde veio o IP quando a Ana rodou ping roteador?

Resumo

  • /etc/hosts mapeia IP nome apelido… localmente e é consultado antes do DNS.
  • Na máquina da Ana: 192.168.1.1 roteador gateway — por isso ping roteador responde 192.168.1.1.
  • Usos: testar sites locais, apelidos na rede, bloquear sites. Exige admin e vale só no computador local.
