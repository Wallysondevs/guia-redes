HTTP: a conversa entre navegador e servidor

Depois que o DNS traduz o nome em IP e a porta certa é achada, começa a conversa de verdade: o protocolo HTTP (HyperText Transfer Protocol). É um formato de cartas padronizadas: o cliente envia uma carta de pedido, o servidor responde com uma carta de resposta. Nesta aula você abre as duas cartas.

Você vai aprender
  • O que é o HTTP: protocolo de pedido/resposta usado por sites e APIs.
  • A requisição: linha de pedido (GET / HTTP/1.1), cabeçalhos e (às vezes) corpo.
  • A resposta: linha de status (HTTP/1.1 200 OK), cabeçalhos e o corpo (o HTML da página).
  • Métodos principais: GET (pedir), POST (enviar dados), e os códigos de status: 200, 301, 404, 500.
  • Ver a conversa inteira com curl -i no simulador — inclusive um 404 de verdade.

A analogia da carta

O HTTP é como um modelo de carta com campos obrigatórios:

  • A primeira linha do pedido: GET / HTTP/1.1 — "quero (GET) a página inicial (/) usando a versão 1.1 do HTTP".
  • Cabeçalhos do pedido: Host: exemplo.com, User-Agent: Mozilla/…, Accept: text/html — como o remetente e os bilhetes do envelope.
  • A resposta vem no mesmo formato: primeira linha com o status (HTTP/1.1 200 OK = "deu certo"), cabeçalhos (Content-Type: text/html, Content-Length: 1256) e, no fim, o corpo: o HTML da página.

A requisição: o pedido do cliente

GET
O método: a ação. GET = "me dá esse recurso". Outros: POST (envia dados, ex.: formulário de login), PUT, DELETE.
/caminho
O recurso pedido dentro do servidor (a página, a API…).
HTTP/1.1
A versão do protocolo. Hoje sites HTTPS usam HTTP/2 ou HTTP/3.
Host: exemplo.com
Cabeçalho obrigatório que diz qual site dentro do servidor (um mesmo IP pode hospedar vários sites).

A resposta: o que o servidor manda de volta

$ curl -i exemplo.com
HTTP/1.1 200 OK
Server: nginx/1.25.3
Content-Type: text/html; charset=UTF-8
Content-Length: 1256
Connection: keep-alive

<html><head><title>Exemplo</title></head><body><h1>Exemplo.com</h1><p>Esta é uma página fictícia do simulador.</p></body></html>

Peças da resposta:

  • HTTP/1.1 200 OK — a linha de status: versão, código numérico e frase. 200 = deu certo.
  • Cabeçalhos: Server (quem atendeu), Content-Type (que tipo de arquivo vem), Content-Length (tamanho em bytes).
  • Corpo (depois da linha em branco): o conteúdo de verdade — aqui, o HTML da página.

Códigos de status: a primeira linha da resposta

CódigoSignificadoQuando você vê
200 OKDeu certo, segue o conteúdoQuase sempre que tudo funciona
301/308"Mudei de endereço" (redirecionamento)http:// vira https://, ou site mudou de domínio
404 Not Found"Não achei esse recurso"Link quebrado, página apagada
500Erro interno do servidorO site caiu do ar

Missão: digite curl -i exemplo.com e aperte Enter. A primeira linha da resposta é o status HTTP/1.1 200 OK — o servidor achou a página.

Quando o recurso não existe: o 404

Pedir um caminho que o servidor não tem devolve 404 Not Found — a página do erro:

$ curl -i http://exemplo.com/nao-existe
HTTP/1.1 404 Not Found
Server: nginx/1.25.3
Content-Type: text/html

<html><body><h1>404 Not Found</h1></body></html>

Missão: digite curl -i http://exemplo.com/nao-existe e aperte Enter. O servidor responde 404 Not Found — o recurso não existe, mas a conversa funcionou.

Resumo

  • HTTP é o protocolo de pedido/resposta da web: o cliente manda uma requisição, o servidor manda uma resposta.
  • Requisição: GET /caminho HTTP/1.1 + cabeçalhos (Host, User-Agent…). Métodos: GET, POST, PUT, DELETE…
  • Resposta: linha de status (200 OK, 404 Not Found, 500…) + cabeçalhos + corpo (o HTML).
  • curl -i exemplo.com mostra a resposta inteira: status, cabeçalhos e corpo.
