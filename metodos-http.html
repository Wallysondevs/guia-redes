Métodos HTTP — o verbo da requisição

Toda requisição HTTP começa com uma linha de comando que traz um método (ou verbo): ele diz o que o cliente quer fazer com aquele endereço. Pense no correio: a URL é o endereço do envelope e o método é a instrução — "leia isto", "cadastre isto", "troque isto", "apague isto".

Você vai aprender
  • Os 5 métodos principais: GET, POST, PUT, PATCH, DELETE.
  • A ler a linha de requisição: GET /usuarios HTTP/1.1.
  • Quais métodos são seguros (não mudam nada no servidor) e quais são idempotentes.
  • Usar curl -X METODO para mandar cada verbo — na API fictícia api.exemplo.com.
  • O que o servidor responde quando você pede algo que não existe (404).

A linha de requisição

Quando o navegador ou o curl conversa com um servidor, a primeira linha do papo é assim:

GET
O método (verbo): aqui, "quero ler".
/usuarios
O caminho do recurso dentro do servidor.
HTTP/1.1
A versão do protocolo usada nessa conversa.

O curl manda GET por padrão. Para mandar outro verbo, use -X:

$ curl -v -X POST -d '{"nome":"Ana"}' https://api.exemplo.com/usuarios
* Trying 93.184.216.35:443...
* Connected to api.exemplo.com (93.184.216.35) port 443
> POST api.exemplo.com/usuarios HTTP/1.1
> Host: api.exemplo.com
> User-Agent: curl/8.5.0
> Accept: */*
> Content-Type: application/json
> Content-Length: 15
>
[{"id":1,"nome":"Ana"},{"id":2,"nome":"Beto"},{"id":3,"nome":"Carla"}]
* Connection #0 to host api.exemplo.com left intact

Repare na linha que começa com > (mostra o que o curl enviou): o verbo foi POST e o corpo da mensagem levou o JSON {"nome":"Ana"}.

Os cinco métodos principais

Cada método é uma intenção diferente. A tabela resume:

MétodoO que fazSeguro?Idempotente?Exemplo do dia a dia
GETLê / pede um recurso. Não deve mudar nada no servidor.simsimAbrir uma página, listar usuários, ver um perfil.
POSTCria um recurso novo.nãonãoCadastrar usuário, enviar formulário, fazer login.
PUTSubstitui o recurso inteiro.nãosimTrocar o perfil completo de uma vez.
PATCHAltera parte do recurso.nãonãoMudar só o e-mail do cadastro.
DELETEApaga o recurso.nãosimRemover um usuário ou um produto.
  • Seguro = não altera o estado do servidor (GET, HEAD, OPTIONS). É como olhar uma vitrine: você não leva nada embora.
  • Idempotente = repetir a mesma requisição dá o mesmo resultado final (PUT e DELETE: repetir não muda a longo prazo). POST não é idempotente: cada POST cria um registro novo.

Na prática: a API fictícia api.exemplo.com

A máquina da Ana consegue falar com a API fictícia https://api.exemplo.com. Veja os verbos em ação:

$ curl -i https://api.exemplo.com/usuarios
HTTP/2 200
content-type: application/json
content-length: 87

[{"id":1,"nome":"Ana"},{"id":2,"nome":"Beto"},{"id":3,"nome":"Carla"}]
$ curl -i -X DELETE https://api.exemplo.com/usuarios/999
HTTP/2 404
content-type: application/json

{"erro":"usuário não encontrado"}

O GET listou os usuários (200 OK). O DELETE tentou apagar o usuário 999 — que não existe — e o servidor respondeu 404 (veja a aula Códigos de status).

Missão: faça um GET (o padrão do curl) em http://exemplo.com e veja o 200 OK com os headers: curl -i http://exemplo.com

Missão: mande um POST com JSON para a API e veja o verbo aparecer na conversa: curl -v -X POST -d '{"nome":"Ana"}' https://api.exemplo.com/usuarios

Missão: tente apagar um usuário que não existe com DELETE e veja o 404: curl -i -X DELETE https://api.exemplo.com/usuarios/999

Missão: use PUT para substituir a lista inteira de usuários: curl -i -X PUT -d '{"nome":"Beto"}' https://api.exemplo.com/usuarios

CUIDADO: nunca use GET para ações que mudam algo no servidor (tipo /apagar?id=5) — GET pode ser disparado por engano (links, prefetch do navegador, crawlers) e precisa ser seguro. Apagar é DELETE (ou POST), e sempre por HTTPS (aula HTTPS/TLS).

Qual método cria um recurso novo no servidor?

Qual método é seguro (não altera nada no servidor) e idempotente?

Resumo

  • Toda requisição começa com MÉTODO caminho HTTP/x.y — o método é a intenção.
  • GET lê (seguro, idempotente); POST cria; PUT substitui inteiro (idempotente); PATCH altera parcial; DELETE apaga (idempotente).
  • No curl: -X POST, -X PUT… e -d 'dados' para mandar o corpo. Sem -X, o curl faz GET.
  • Apagar algo que não existe devolve 404 — o servidor está dizendo "não achei esse recurso".
