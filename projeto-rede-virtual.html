Projeto 4 — rede virtual entre duas VMs (VirtualBox)

Até agora a Ana falava com máquinas da internet. E se você quiser duas máquinas suas conversando entre si, sem sair para a internet — como duas bancadas de trabalho ligadas por um cabo de rede só entre elas? É exatamente o que a placa de rede "Rede interna" (intnet) do VirtualBox faz: um switch virtual dentro do seu computador.

Você vai aprender
  • Os modos de rede do VirtualBox e quando usar Rede interna (só as VMs se enxergam).
  • A configurar IP fixo nas duas VMs da mesma sub-rede (192.168.1.50 e 192.168.1.60/24).
  • A testar a conectividade com ping 192.168.1.60 — o ping mostra o IP entre parênteses.
  • A entrar numa VM a partir da outra com ssh ana@192.168.1.60.
  • A conferir tudo com ip addr e arp (a tabela de vizinhos da rede local).

Passo 1 — criar a segunda VM e a rede interna

No VirtualBox: Máquina → Nova crie uma segunda VM (ex.: "vm2", Ubuntu Server). Com as duas desligadas, vá em Configurações → Rede → Adaptador 1 de cada uma e escolha:

Modo: Rede interna
Cria uma rede virtual só entre as VMs do seu computador (nome padrão intnet). Não há acesso à internet por esse adaptador — é um cabo direto entre as máquinas.
Modo: Placa em modo bridge
A VM entra na sua rede real (ganha IP do roteador) — serve para a VM falar com a internet e com o host.
Modo: NAT
A VM sai para a internet "por trás" do host, mas não é alcançável de fora — o padrão do VirtualBox.

Para este projeto, deixe as duas VMs com o Adaptador 1 em "Rede interna" (nome intnet).

Passo 2 — IPs na mesma sub-rede

Ligue as duas VMs. Sem DHCP nessa rede interna, configure IP fixo em cada uma (ou ligue o DHCP do VirtualBox em Configurações → Rede → DHCP). Na vm1 (a máquina da Ana) já temos 192.168.1.50/24; na vm2 configure 192.168.1.60/24:

# na vm2:
$ sudo ip addr add 192.168.1.60/24 dev enp0s3
$ sudo ip link set enp0s3 up
$ ip addr show enp0s3
2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 state UP
    inet 192.168.1.60/24 scope global enp0s3

Mesma sub-rede (/24 = 192.168.1.0/24) significa: "estamos no mesmo corredor, dá para falar direto, sem roteador no meio".

Passo 3 — pingar a outra VM

Na vm1, teste a comunicação. O ping manda pacotes ICMP; se a vm2 responder, aparece 64 bytes from …:

$ ping -c 3 192.168.1.60
PING 192.168.1.60 (192.168.1.60) 56(84) bytes of data.
64 bytes from 192.168.1.60: icmp_seq=1 ttl=64 time=0.42 ms
64 bytes from 192.168.1.60: icmp_seq=2 ttl=64 time=0.38 ms
64 bytes from 192.168.1.60: icmp_seq=3 ttl=64 time=0.51 ms

--- 192.168.1.60 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss

Repare: como você digitou o IP direto, não houve consulta DNS — o ping foi direto na rede local. Tempo de 0,4 ms é o typical de duas VMs no mesmo host.

Missão: no simulador (a máquina da Ana), rode ping 192.168.1.60 — o servidorzinho do projeto 3 — e veja as linhas 64 bytes from 192.168.1.60.

Passo 4 — entrar na outra máquina com SSH

Com a rede no ar, a Ana acessa a vm2 por SSH (porta 22) sem sair da vm1:

$ ssh ana@192.168.1.60
ana@192.168.1.60's password:
Welcome to Ubuntu 24.04 LTS (vm2)
ana@vm2:~$ hostname
vm2
ana@vm2:~$ exit

O SSH cifra a conexão — diferente do telnet, onde a senha passa em texto puro pela rede (aula TCP vs UDP e HTTPS/TLS explicam por quê isso importa).

Missão: rode ssh ana@192.168.1.60 no simulador e veja a mensagem de conexão simulada.

Passo 5 — conferindo a vizinhança: arp

Depois do ping, a vm1 guardou o endereço MAC da vm2 na tabela ARP (a "lista de quem mora no meu corredor" da camada 2):

$ arp -a
Address                  HWtype  HWaddress           Flags Mask  Iface
192.168.1.1              ether   00:11:22:33:44:55   C          eth0
192.168.1.60             ether   66:77:88:99:aa:bb   C          eth0

Missão: rode arp (ou arp -a) no simulador e ache o MAC de 192.168.1.60.

Se o ping falhar entre as VMs: confira, na ordem — (1) as duas estão no mesmo modo "Rede interna" e com o mesmo nome de rede (intnet); (2) os IPs estão na mesma sub-rede (ip addr nas duas); (3) o firewall da VM destino não bloqueia ICMP/SSH (porta 22). Na máquina real, ss -tlnp na vm2 mostra se o sshd está ouvindo. Veja a página Problemas comuns.

Resumo do projeto

  • Rede interna do VirtualBox = switch virtual só entre VMs (sem internet).
  • Mesma sub-rede → comunicação direta: ping 192.168.1.60 responde 64 bytes from.
  • ssh ana@192.168.1.60 entra na outra VM pela porta 22.
  • ip addr confere os IPs; arp mostra os vizinhos descobertos.
