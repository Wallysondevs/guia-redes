Firewall: iptables/nftables básico

Até aqui o pacote viajava livremente. Mas e se você quiser proibir certas entradas? A máquina precisa de um porteiro: isso é o firewall. No Linux, o porteiro clássico é o iptables (e o sucessor moderno, o nftables). Analogia: é a portaria de um prédio — só entra quem está na lista, pela porta certa, e tudo que não está permitido é barrado.

Você vai aprender
  • O que é um firewall de pacotes e onde ele fica (na própria máquina, camada 3/4);
  • As cadeias INPUT, OUTPUT, FORWARD e a política padrão (ACCEPT/DROP);
  • Comandos reais de iptables e nft para um servidor web;
  • A regra de ouro: a primeira regra que casa vale — ordem importa;
  • O perigo de editar firewall remoto por SSH (trancar a si mesmo para fora).

Como o firewall decide

Cada pacote que chega (ou sai) passa por uma cadeia de regras. O firewall lê as regras de cima para baixo e aplica a primeira que "casar" com o pacote; se nenhuma casar, vale a política padrão da cadeia. As cadeias principais:

CadeiaQuando o pacote passa por ela
INPUTPacote entrando na máquina e destinado a ela mesma (ex.: alguém tentando seu SSH na porta 22).
OUTPUTPacote saindo da máquina (ex.: seu ping ou curl para fora).
FORWARDPacote que chega numa interface e vai sair por outra (a máquina servindo de roteador/NAT — aula NAT).
Regra
Um teste + uma ação: "se for TCP, porta 22, protocolo TCP → ACCEPT". O teste olha IP de origem, porta, protocolo, interface…
ACCEPT / DROP
ACCEPT deixa passar; DROP descarta silenciosamente (o remetente nem fica sabendo — dá timeout). Existe também REJECT, que descarta mas avisa com ICMP (útil em testes, barulhento em produção).
Política padrão (policy)
Se nenhuma regra casar: DROP (seguro, "bloqueia por padrão") ou ACCEPT (permissivo). A boa prática é INPUT com política DROP e liberar só o necessário.

iptables na prática (comandos reais)

Estes comandos rodam num Linux real (não no simulador — aqui vamos só visualizar). Primeiro, ver o que já existe:

$ sudo iptables -L -v --line-numbers
Chain INPUT (policy ACCEPT 0 packets, 0 bytes)
num   pkts bytes target     prot opt in     out     source               destination
1     …                              /* regras aqui */

$ sudo iptables -L INPUT -n -v | head
Chain INPUT (policy DROP 120 packets, 4800 bytes)   « política padrão: bloqueia o resto

Um conjunto básico e seguro para um servidor web (rode nessa ordem!):

$ sudo iptables -P INPUT DROP          # política padrão: NINGUÉM entra
$ sudo iptables -P FORWARD DROP        # e não roteia nada
$ sudo iptables -P OUTPUT ACCEPT       # a máquina pode sair (senão trava tudo)
$ sudo iptables -A INPUT -i lo -j ACCEPT              # loopback sempre livre
$ sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
                                            # deixa voltar as respostas das conexões já abertas
$ sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT   # SSH (a porta do porteiro!)
$ sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT   # HTTP
$ sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT  # HTTPS
$ sudo iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT  # ping
$ sudo iptables -A INPUT -j LOG --log-prefix "FIREWALL-DROP: "   # loga o que foi barrado
$ sudo iptables -L -v -n               # confere tudo

E para a sua rede local sair para a internet com um IP público só (NAT — aula NAT):

$ sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
$ sudo iptables -A FORWARD -i eth0 -o eth1 -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
$ sudo iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT
$ sudo iptables-save > /etc/iptables/rules.v4   # salva as regras
ComandoPara que serve
iptables -L -v -n --line-numbersLista as regras (com números, para apagar depois).
iptables -P INPUT DROPDefine a política padrão da cadeia (bloqueia tudo que não casar).
-A INPUT -p tcp --dport 443 -j ACCEPTAcrescenta regra no fim da cadeia INPUT: TCP porta 443 entra.
-m conntrack --ctstate ESTABLISHED,RELATEDSó deixa passar pacotes de conexões já existentes (respostas) — detalhe crucial para não travar a própria saída.
-j LOG --log-prefix "…"Registra no log do sistema o que foi descartado (diagnóstico).
-t nat -A POSTROUTING -j MASQUERADENAT: troca o IP de origem dos pacotes que saem pela interface.
-D INPUT 3Apaga a regra número 3 da cadeia INPUT.
iptables-save / iptables-restoreSalva e restaura todas as regras (persistência).

nftables: o sucessor moderno

O nft substitui o iptables aos poucos (sintaxe única, mais simples). Equivalentes:

$ sudo nft list ruleset
table inet filtro {
  chain input {
    type filter hook input priority 0; policy drop;
    iif "lo" accept
    ct state established,related accept
    tcp dport { 22, 80, 443 } accept
    icmp type echo-request accept
  }
}

Firewall de rede vs firewall da máquina

O iptables/nft roda na própria máquina (firewall de host). Empresas também usam firewall de rede (um equipamento dedicado na borda, ex.: pfSense, Fortinet, Cisco ASA) que filtra o tráfego de toda a rede antes de chegar nas máquinas. Os dois se somam: a portaria do prédio e a fechadura da sua porta.

Missão: rode ss -tlnp no simulador e veja as portas que a máquina da Ana está escutando (22/SSH e 8000/HTTP). São essas portas que o firewall precisaria deixar passar (-p tcp --dport 22 -j ACCEPT) — ou bloquear, no caso de um servidor público.

Não tranque a porta atrás de você!

Se você está num servidor remoto conectado por SSH e aplica -P INPUT DROP sem liberar a porta 22 antes, você perde o acesso na hora — e só volta com acesso físico/console. Regra de ouro: (1) teste as regras localmente ou numa VM primeiro; (2) ao aplicar remotamente, mantenha uma segunda sessão aberta para reverter; (3) use iptables -A INPUT -p tcp --dport 22 -j ACCEPT antes de mudar a política; (4) muitos admins colocam um "timer de segurança" (ex.: at) que restaura as regras antigas em 10 minutos, caso dê tudo errado.

Resumo

  • Firewall de host (iptables/nft) filtra pacotes na própria máquina: cadeias INPUT / OUTPUT / FORWARD + política padrão.
  • Regras são lidas em ordem e a primeira que casa vale; boa prática: política DROP no INPUT e liberar só o necessário (lo, conexões existentes, 22/80/443, ICMP).
  • conntrack ESTABLISHED,RELATED deixa voltar as respostas — sem isso, até a própria saída trava.
  • MASQUERADE faz o NAT da sua rede para a internet; nft é o sucessor moderno do iptables.
  • Nunca mude a política padrão remotamente sem garantir a porta do seu acesso (SSH) — ou você fica trancado para fora.
