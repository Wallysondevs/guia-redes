Wireshark: tcpdump com interface gráfica

O tcpdump imprime texto cru no terminal — ótimo para scripts, ruim para explorar. O Wireshark é o mesmo tcpdump com interface gráfica: ele captura ao vivo ou abre um arquivo .pcap (gerado pelo tcpdump -w) e mostra cada pacote numa janela com cores, filtros clicáveis e os detalhes de cada camada. Pense nele como a lupa de detetive da rede: você vê o handshake, a consulta DNS, o pedido HTTP — tudo separado bonitinho.

Você vai aprender
  • Os 3 painéis do Wireshark: lista de pacotes, detalhes (árvore de camadas) e bytes em hex.
  • Filtros de exibição: dns, tcp.port == 443, ip.addr == 192.168.1.50, tcp.flags.syn == 1.
  • Follow TCP Stream: remontar a conversa inteira (o HTTP dentro do TCP).
  • Como instalar e dar permissão de captura sem sudo.
  • A ética: só capture tráfego da sua própria rede, com permissão.

Os 3 painéis da tela

PainelO que mostraColunas/linhas típicas
1. Lista de pacotes (em cima)Uma linha por pacote capturado, colorida por protocoloNo. · Time · Source · Destination · Protocol · Length · Info
2. Detalhes do pacote (meio)O pacote desmontado camada por camada: Ethernet → IP → TCP/UDP → aplicação (DNS, HTTP…)Frame → Ethernet II → Internet Protocol v4 → Transmission Control Protocol → Hypertext Transfer Protocol
3. Bytes (embaixo)O pacote em hexadecimal e ASCII, byte a byteoffset em hex + bytes + texto legível

Clicar numa linha do painel 1 mostra aquele pacote nos painéis 2 e 3; clicar numa camada no painel 2 destaca os bytes dela no painel 3. É assim que você "desembrulha" o pacote: o endereço MAC no quadro Ethernet, o IP no pacote, a porta no segmento TCP, o pedido HTTP dentro dos dados.

Filtrando na tela (filtros de exibição)

Diferente do tcpdump (que filtra na captura), o Wireshark filtra na exibição — a captura continua completa, você só esconde linhas. Filtros úteis:

FiltroMostra só…
dnsconsultas e respostas DNS (porta 53)
tcp.port == 443pacotes TCP da porta 443 (HTTPS)
ip.addr == 192.168.1.50todo pacote que tem o IP da Ana (origem ou destino)
tcp.flags.syn == 1somente os SYN — você vê só os handshakes (aberturas de conexão)
http ou http.requestpedidos HTTP (GET, POST…)
tcp.stream eq 0uma conversa TCP inteira, do início ao fim

As linhas ficam coloridas por protocolo (verde claro = TCP comum, preto = com erro, etc.) — dá para mudar em View → Coloring Rules.

Follow TCP Stream: a conversa remontada

O truque mais famoso: clique com o botão direito num pacote TCP e escolha Follow → TCP Stream. O Wireshark junta todos os pacotes daquela conexão (identificada pelo par de sockets) e mostra o conteúdo em texto plano, como se fosse um chat — é assim que se lê o pedido HTTP que o navegador mandou, linha por linha (GET / HTTP/1.1, Host: …, cabeçalhos…).

Instalando e capturando sem sudo

  • Linux (Debian/Ubuntu): sudo apt install wireshark — durante a instalação, diga "sim" para permitir que usuários comuns capturem; ou depois adicione seu usuário ao grupo: sudo usermod -aG wireshark $USER (precisa sair e entrar de novo).
  • macOS / Windows: baixe o instalador oficial em wireshark.org (no Windows, o Npcap vem junto e dá a permissão de captura).
  • Para analisar um arquivo pronto (em vez de capturar ao vivo): File → Open e escolha o .pcap gravado pelo tcpdump -w captura.pcap (aula tcpdump).

Treine no simulador: gere tráfego para capturar

O simulador não tem Wireshark (é gráfico), mas tem o tcpdump — que gera exatamente o mesmo tipo de captura. Gere tráfego e "veja" os pacotes:

$ tcpdump -i eth0
tcpdump: listening on eth0, link-type EN10MB (Ethernet), snapshot length 262144 bytes
10:15:01.100001 IP 192.168.1.50.54321 > 93.184.216.34.443: Flags [S], seq 1548213, win 64240, length 0
10:15:01.123456 IP 93.184.216.34.443 > 192.168.1.50.54321: Flags [S.], seq 9921045, ack 1548214, win 65535, length 0
10:15:01.123500 IP 192.168.1.50.54321 > 93.184.216.34.443: Flags [.], ack 9921046, win 64240, length 0

Num Wireshark de verdade, essas mesmas 3 linhas seriam o handshake TCP que vimos na aula SYN/SYN-ACK/ACK — só que clicáveis, coloridas e com cada campo explicado.

Missão: rode tcpdump -i eth0 no terminal simulado — é a mesma captura que o Wireshark mostraria em gráfico, só que em texto.

Missão: rode nmap exemplo.com — o scan gera um monte de pacotes novos (SYN para várias portas). Se estivesse capturando com tcpdump/Wireshark agora, você veria todos eles na tela.

Ética e legalidade

Capturar tráfego de rede de outras pessoas sem permissão é crime (interceptação de telecomunicações) e antiético. Use o Wireshark/tcpdump só na sua própria máquina/rede, em ambientes de laboratório, ou com autorização explícita — é a ferramenta de diagnóstico, não de bisbilhotar.

Resumo

  • Wireshark = tcpdump com GUI: captura ao vivo ou abre .pcap; 3 painéis (lista, camadas, hex).
  • Filtros de exibição: dns, tcp.port == 443, ip.addr == …, tcp.flags.syn == 1.
  • Follow TCP Stream remonta a conversa inteira (ex.: o pedido HTTP dentro do TCP).
  • Instale com apt install wireshark (Linux) ou pelo site oficial; capture só sua própria rede.
  • No simulador, o tcpdump mostra os mesmos pacotes em texto.
