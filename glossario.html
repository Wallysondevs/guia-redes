Glossário de redes, de A a Z

Todo guia de redes usa os mesmos termos o tempo inteiro — e eles voltam em todo canto: nos comandos, nos erros, nas conversas de trabalho. Este glossário reúne os termos essenciais em ordem alfabética, com definição em português claro e, quando faz sentido, um exemplo na máquina da Ana (ana@notebook, IP 192.168.1.50). Consulte sempre que um termo novo aparecer.

Você vai aprender
  • Endereçamento: IP, IPv4, IPv6, MAC, máscara, sub-rede, CIDR.
  • Conexão e transporte: porta, socket, TCP, UDP, handshake, TTL, latência.
  • Aplicação: DNS, DHCP, HTTP/HTTPS, header, URL, proxy, VPN.
  • Diagnóstico: ping, traceroute (hop), pacote, ARP, rota/gateway, NAT, firewall.

Os termos, de A a Z

ARP (Address Resolution Protocol)
Protocolo que traduz IP em endereço MAC na rede local: "quem tem o IP 192.168.1.60?" → "eu, meu MAC é 66:77:88:99:aa:bb". Veja com arp -a. É a lista de vizinhos do corredor.
Banda (largura de banda)
Capacidade máxima de transferência de um link, medida em bits por segundo (Mbps/Gbps). É a largura da estrada: não muda a velocidade do carro, muda quantos carros passam por segundo.
Cliente-servidor
O modelo da internet: o cliente (seu navegador) pede; o servidor (um computador na rede) atende. O servidor fica ouvindo numa porta (ex.: 443) esperando pedidos.
CIDR (Classless Inter-Domain Routing)
A notação /24 depois do IP (ex.: 192.168.1.50/24): diz quantos bits são da rede. /24 = 256 endereços (192.168.1.0–255).
DHCP
Protocolo que entrega IP automático para os dispositivos da rede (portas UDP 67/68). Foi o DHCP do roteador que deu 192.168.1.50 ao notebook da Ana — sem ele, cada máquina teria que ser configurada na mão.
DNS (Domain Name System)
O sistema que traduz nomes em IPs — a agenda telefônica da internet (porta 53, TCP e UDP). exemplo.com → 93.184.216.34. Consulte com dig e nslookup; apelidos locais ficam no /etc/hosts.
Encapsulamento
Cada camada da rede embrulha os dados da camada de cima num "envelope" próprio (HTTP dentro de TCP dentro de IP dentro de Ethernet). É como mandar uma carta dentro de um pacote dentro de uma caixa.
Firewall
O "porteiro" da rede: filtra pacotes por IP, porta e protocolo, decidindo o que entra e sai. O notebook da Ana bloqueia a 8000 de fora, mas deixa o navegador acessar — aula firewall.
Gateway (gateway padrão)
O endereço para onde vão os pacotes que não são da rede local — o "portão para fora do condomínio". No notebook da Ana é 192.168.1.1 (veja ip route: default via 192.168.1.1).
Handshake TCP
A troca de 3 mensagens (SYN → SYN-ACK → ACK) que abre uma conexão TCP antes de mandar dados — como um "alô? pode falar? pode" antes da conversa. Aula handshake.
Header (cabeçalho)
Linhas Nome: valor no início de um pedido/resposta HTTP (e de outros protocolos) — o "envelope" da mensagem. Ex.: Host: exemplo.com, Content-Type: application/json. Veja a cola de headers.
Hop (salto)
Cada roteador que um pacote atravessa até o destino. O traceroute lista os saltos: 192.168.1.1 → 189.50.10.1 → … → 93.184.216.34.
HTTP / HTTPS
O protocolo da web: pedidos (GET, POST…) e respostas (status 200, 404…) em texto, na porta 80. O HTTPS é o mesmo protocolo na porta 443, criptografado por TLS — cadeado verde no navegador.
ICMP
Protocolo de mensagens de controle da rede (não manda dados de app). O ping usa ICMP (echo request/reply) para testar se o host responde; o traceroute usa o TTL do ICMP/IP.
IP (Internet Protocol)
O protocolo que endereça e roteia pacotes na internet. Cada máquina tem um IP único na rede — o notebook da Ana é 192.168.1.50 (veja ip addr).
IPv4
A versão 4 do IP: 4 números de 0–255 (ex.: 192.168.1.50), ~4,3 bilhões de endereços. É o que o guia usa nos exemplos.
IPv6
A versão 6 do IP: 8 grupos hexadecimais (ex.: 2001:0db8::1), com endereços praticamente infinitos. Registro DNS desse tipo é o AAAA.
Latência
O tempo que um pacote leva para ir e voltar (medido em ms). O ping mostra: time=23.4 ms. Não é banda — é o atraso (a distância + filas no caminho).
MAC (endereço físico)
O endereço gravado na placa de rede (ex.: aa:bb:cc:dd:ee:ff), único no mundo, usado só na rede local (camada 2). Veja em ip addr como link/ether.
Máscara de sub-rede
Diz quais bits do IP são da rede e quais são da máquina. 255.255.255.0 = /24: os 3 primeiros números são a rede (192.168.1.x), o último é a máquina.
NAT (Network Address Translation)
A tradução de endereços que o roteador faz: os dispositivos da casa usam IPs privados (192.168.1.x) e o roteador troca pelo IP público ao sair para a internet — como um balcão de correspondências do prédio.
Pacote
A unidade de dados que viaja na rede: um envelope (IP) com um segmento (TCP/UDP) dentro, que carrega um pedaço da sua mensagem (HTTP). O tcpdump mostra os pacotes um a um.
Ping
O comando de teste mais famoso: manda ICMP echo e mede se o host responde e em quanto tempo (64 bytes from … time=23.4 ms). "Pingar" virou sinônimo de "testar se está no ar".
Porta
O número (0–65535) que identifica um serviço dentro de um IP — a sala do prédio. Web = 80/443, SSH = 22, DNS = 53. Veja ss -tlnp e a cola de portas.
Protocolo
O conjunto de regras que dois lados seguem para conversar: TCP, UDP, IP, HTTP, DNS, TLS… Cada um define o formato das mensagens e a ordem delas.
Proxy
Um intermediário que faz pedidos em nome de outra máquina — filtra, cacheia ou esconde a origem (proxy direto) ou esconde o destino (proxy reverso, na frente de servidores). Aula proxy reverso.
Registro DNS
Um "cartão" na agenda do DNS: A (IPv4), AAAA (IPv6), CNAME (apelido), MX (e-mail), TXT (texto), NS, SOA, PTR. Cola em registros DNS.
Rota
O caminho que um pacote segue até o destino, decidido pela tabela de rotas de cada máquina/roteador (ip route). A rota padrão (default) manda o resto para o gateway.
Roteador
O equipamento que conecta redes diferentes e encaminha pacotes entre elas (faz o papel de gateway). O roteador de casa da Ana é o 192.168.1.1.
Servidor
Um programa (ou máquina) que fica ouvindo numa porta e atende pedidos — o oposto do cliente. Ex.: o python3 -m http.server 8000 do projeto 1 é um servidor web na porta 8000.
Socket
O par IP:porta que identifica uma ponta de uma conexão (ex.: 192.168.1.50:54321 ↔ 93.184.216.34:443). O comando ss lista os sockets da máquina (socket statistics).
Sub-rede
Um pedaço de uma rede IP (ex.: 192.168.1.0/24 = 256 IPs). Quem está na mesma sub-rede fala direto; para sair dela, passa pelo gateway.
TCP
Protocolo de transporte confiável e orientado a conexão: handshake antes, confirmação de entrega, reenvio se perder (a carta registrada). Usado por HTTP/HTTPS, SSH, e-mail. Aula TCP vs UDP.
TTL (Time To Live)
Campo do pacote IP que conta quantos roteadores ele ainda pode atravessar (evita pacote ficar rodando para sempre). No ping aparece como ttl=64; no DNS, é o tempo de cache do registro.
UDP
Protocolo de transporte sem conexão e sem garantia de entrega — rápido e leve (a carta simples, sem aviso de recebimento). Usado por DNS, streaming, jogos, VoIP.
URL
O endereço completo de um recurso na web: https://exemplo.com:443/caminho?busca=1 = protocolo + domínio + porta + caminho + consulta. Aula anatomia da URL.
VPN
Rede privada virtual: um túnel criptografado dentro da internet, ligando máquinas distantes como se estivessem na mesma rede local. Aula VPN.

Os pares que mais confundem

  • IP × MAC: IP é o endereço lógico na internet (muda de rede); MAC é o endereço físico da placa, só vale na rede local.
  • TCP × UDP: TCP confirma entrega (confiável, mais lento); UDP manda e esquece (rápido, sem garantia).
  • DNS × /etc/hosts: o hosts é a agenda local do seu computador (consultada antes); o DNS é a agenda da internet.
  • Porta 80 × porta 443: HTTP (texto puro) × HTTPS (criptografado).
  • Gateway × DNS: gateway é para onde vão os pacotes de fora da rede local; DNS é quem traduz nomes em IPs (muitas vezes os dois são o mesmo roteador, como o 192.168.1.1).
  • 404 × "site fora do ar": 404 significa que a conexão funcionou e o servidor respondeu — só a página não existe. "Fora do ar" é curl: (7) Connection refused ou timeout no ping.
