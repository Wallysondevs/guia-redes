ARP: de IP para MAC

O IP é o endereço lógico ("apartamento 192.168.1.1"), mas a placa de rede só entende endereços físicos: o MAC (ex.: 00:11:22:33:44:55) — pense nele como a placa do carro na garagem do prédio. Dentro da rede local, para entregar um pacote ao vizinho, o computador precisa traduzir o IP em MAC. Quem faz essa tradução é o ARP (Address Resolution Protocol): o computador pergunta em voz alta na rede — "quem tem o IP 192.168.1.1?" (pergunta em broadcast, para todos) — e o dono responde "sou eu! meu MAC é 00:11:22:33:44:55". A resposta fica anotada numa tabelinha, a tabela ARP.

Você vai aprender
  • O que é o endereço MAC (48 bits, único por placa de rede, ex.: aa:bb:cc:dd:ee:ff).
  • Como o ARP funciona: ARP request em broadcast + ARP reply com o MAC.
  • A ver a tabela ARP com arp -a.
  • Por que o ARP só vale dentro da rede local: para destinos de fora, o MAC usado é o do gateway.

O passo a passo na rede da Ana

O notebook (192.168.1.50, MAC aa:bb:cc:dd:ee:ff) quer mandar um pacote para o roteador (192.168.1.1), que está na mesma sub-rede /24:

1. Consulta a tabela ARP
O notebook olha a própria tabelinha: "já sei o MAC do 192.168.1.1?" Se não souber, segue.
2. ARP request (broadcast)
Manda para todos da rede (MAC de destino ff:ff:ff:ff:ff:ff): "Quem tem o IP 192.168.1.1? Responda para 192.168.1.50".
3. ARP reply (unicast)
Só o roteador responde, direto para o notebook: "192.168.1.1 está no MAC 00:11:22:33:44:55".
4. Tabela ARP atualizada
O notebook grava 192.168.1.1 → 00:11:22:33:44:55 na tabela (por alguns minutos) e manda o pacote encapsulado no quadro Ethernet com esse MAC de destino.

ARP só funciona dentro da rede local

O ARP request é um broadcast — e broadcast não atravessa roteador. Então, quando o destino está fora da sub-rede (ex.: exemplo.com = 93.184.216.34), o computador não faz ARP do destino: ele faz ARP do gateway (192.168.1.1) e manda o pacote para o MAC do roteador. Quem cuida do resto do caminho é o roteador (aula traceroute). Resumindo:

Destino do pacoteARP de quem é feito?MAC de destino do quadro
Dentro de 192.168.1.0/24 (ex.: 192.168.1.60)Do próprio destinoMAC do destino
Fora da rede (ex.: 93.184.216.34)Do gateway 192.168.1.1MAC do roteador (00:11:22:33:44:55)
Conflito de IP estraga o ARP

Se dois dispositivos da mesma rede tiverem o mesmo IP (ex.: dois 192.168.1.50 configurados na mão), os dois respondem o ARP request — um de cada vez — e a tabela ARP fica alternando entre os dois MACs. Resultado: a conexão fica intermitente, "às vezes abre, às vezes não". A tabela ARP é dinâmica e as entradas expiram, por isso o problema vai e volta.

Resumo

  • MAC = endereço físico da placa de rede (48 bits, único no mundo); IP = endereço lógico da rede.
  • ARP traduz IP → MAC na rede local: pergunta em broadcast, resposta em unicast, resultado guardado na tabela ARP.
  • Veja a tabela com arp -a; o comando ip addr mostra o MAC da sua placa (link/ether).
  • Para destinos fora da sub-rede, o ARP é feito do gateway, não do destino final.
