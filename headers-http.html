Headers — o envelope da mensagem

Toda mensagem HTTP tem duas partes: o corpo (body — o conteúdo em si, a carta) e os headers (cabeçalhos — o envelope: remetente, destinatário, carimbos e instruções como "frágil" ou "urgente"). Nesta aula você aprende a ler os dois lados do envelope.

Você vai aprender
  • O formato de um header: Nome: valor, um por linha.
  • Headers de requisição (o que o cliente manda) e de resposta (o que o servidor devolve).
  • Os mais comuns: Host, User-Agent, Accept, Content-Type, Set-Cookie, Cache-Control…
  • Ver tudo isso no terminal com curl -i e curl -v.

Anatomia de um header

Um header é sempre um par nome: valor:

Content-Type: application/json
Content-Type:
O nome do header (não liga para maiúsculas/minúsculas).
application/json
O valor: aqui, "o corpo desta mensagem é JSON".

O que o cliente envia (requisição)

Com curl -v, as linhas que começam com > mostram os headers que o cliente mandou:

$ curl -v https://exemplo.com
* Trying 93.184.216.34:443...
* Connected to exemplo.com (93.184.216.34) port 443
> GET exemplo.com HTTP/1.1
> Host: exemplo.com
> User-Agent: curl/8.5.0
> Accept: */*
>
* Connection #0 to host exemplo.com left intact
  • Host: exemplo.com — qual site está sendo pedido dentro do servidor (vários domínios podem dividir o mesmo IP).
  • User-Agent: curl/8.5.0 — quem é o cliente ("eu sou o curl, versão 8.5.0").
  • Accept: */* — que tipos de conteúdo o cliente topa receber.

O que o servidor devolve (resposta)

Com curl -i, os headers da resposta aparecem antes do corpo:

$ curl -i http://exemplo.com
HTTP/1.1 200 OK
Server: nginx/1.25.3
Content-Type: text/html; charset=UTF-8
Content-Length: 1256
Connection: keep-alive

<html><head><title>Exemplo</title></head><body><h1>Exemplo.com</h1>...</body></html>
  • HTTP/1.1 200 OK — a linha de status (aula Códigos de status).
  • Server: nginx/1.25.3 — qual servidor atendeu.
  • Content-Type: text/html; charset=UTF-8 — o tipo do corpo que vem a seguir.
  • Content-Length: 1256 — o tamanho do corpo em bytes.
  • Connection: keep-alive — a conexão TCP fica aberta para próximas requisições.

Missão: peça a página com os headers junto: curl -i http://exemplo.com — repare na linha 200 OK e nos headers antes do HTML.

Os headers mais comuns

HeaderLadoPara que serve
HostrequisiçãoDiz qual domínio está sendo pedido (vários sites dividem o mesmo IP).
User-AgentrequisiçãoIdentifica o cliente: navegador, curl, app de celular…
AcceptrequisiçãoTipos de conteúdo aceitos: text/html, application/json…
Content-Typereq. e resp.O tipo do corpo da mensagem (HTML, JSON, imagem…).
Content-LengthrespostaTamanho do corpo em bytes.
AuthorizationrequisiçãoCredencial de acesso (token) — só por HTTPS!
CookierequisiçãoCookies guardados, mandados de volta (aula Cookies e sessões).
Set-CookierespostaManda um cookie novo para o navegador guardar.
Cache-ControlrespostaRegras de cache: "não guarde", "guarde por 1 hora"…
LocationrespostaPara onde redirecionar (vem com 301/302).
Strict-Transport-Securityresposta"Só fale comigo por HTTPS" (HSTS — aula HTTPS/TLS).

Missão: peça o JSON da API e ache o header do tipo de conteúdo: curl -i https://api.exemplo.com/usuarios

Missão: veja os headers que o seu cliente envia (linhas com >): curl -v https://exemplo.com

Missão: ache o header HSTS na resposta HTTPS: curl -i https://exemplo.com (ponte para a aula de HTTPS).

CUIDADO: nunca ponha senha, token ou cookie na URL — a URL aparece no histórico, nos logs do servidor e nos logs do roteador. Mande dados sensíveis no corpo da requisição ou no header Authorization, sempre por HTTPS.

Resumo

  • Header = par Nome: valor, um por linha, no "envelope" da mensagem HTTP (corpo vai depois, em branco).
  • Na requisição o cliente manda Host, User-Agent, Accept, Cookie, Authorization…
  • Na resposta o servidor manda Content-Type, Content-Length, Set-Cookie, Cache-Control, Location…
  • curl -i mostra a resposta com headers; curl -v mostra também o que foi enviado (linhas >).
