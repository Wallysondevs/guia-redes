O handshake de 3 vias: SYN → SYN-ACK → ACK

Antes de mandar qualquer dado, o TCP precisa "ligar o telefone" dos dois lados e combinar os números de série da conversa. A analogia do telefonema: "Alô? Pode falar?" — "Alô, pode sim, e você está me ouvindo?" — "Perfeito, então vamos lá". Essas são as 3 mensagens do handshake: SYN, SYN-ACK e ACK. Só depois delas a conexão vira ESTABLISHED e os dados podem trafegar.

Você vai aprender
  • As 3 etapas do handshake: SYN (seq=x), SYN-ACK (seq=y, ack=x+1), ACK (ack=y+1).
  • Para que servem os números de sequência (seq/ack): ordenar e confirmar cada byte.
  • As flags do TCP vistas no tcpdump: [S], [S.], [.], [P.], [F], [R].
  • Como o tcpdump mostra o handshake na prática.
  • Erros reais: SYN sem resposta (timeout) e resposta RST (porta fechada).

As 3 mensagens, byte a byte

O notebook da Ana (192.168.1.50) abre uma conexão TCP com o servidor do exemplo.com (93.184.216.34, porta 80):

1. SYN (cliente → servidor)
192.168.1.50:54321 → 93.184.216.34:80 Flags [S], seq=x. "Quero abrir uma conexão; meu primeiro número de sequência é x."
2. SYN-ACK (servidor → cliente)
93.184.216.34:80 → 192.168.1.50:54321 Flags [S.], seq=y, ack=x+1. "Pode falar (meu seq é y), e confirme que recebeu até x+1."
3. ACK (cliente → servidor)
192.168.1.50:54321 → 93.184.216.34:80 Flags [.], ack=y+1. "Confirmado, recebido até y+1."

Pronto: a conexão está ESTABLISHED nos dois lados. A partir daí, cada byte enviado vem com um número de sequência e o outro lado responde ack confirmando até onde recebeu — é assim que o TCP garante ordem e nada perdido (aula TCP vs UDP).

Vendo o handshake no tcpdump

O tcpdump (próxima aula, tcpdump) mostra as flags de cada pacote TCP. O início de uma conexão aparece exatamente assim — um [S], um [S.] e um [.]:

Erros reais que o handshake revela
  • SYN sem resposta (timeout): ninguém respondeu — firewall filtrando ou host desligado. No curl aparece Connection timed out.
  • Resposta RST: a porta está fechada no servidor (não tem programa escutando nela). No curl aparece Connection refused — é a máquina dizendo "aqui não mora ninguém nessa porta".

E o fim da conversa?

Para encerrar, cada lado manda um FIN e recebe um ACK (geralmente 4 pacotes, ou 3 se junto). No tcpdump, o fim aparece como Flags [F.] dos dois lados. Se algo dá errado, um lado manda [R] (RST) e a conexão morre na hora.

Resumo

  • Handshake de 3 vias: SYN → SYN-ACK → ACK, que sincroniza os números de sequência (seq/ack) dos dois lados.
  • Só depois do 3º pacote a conexão está ESTABLISHED e os dados podem trafegar.
  • No tcpdump: [S], [S.], [.] = início; [P.] = dados; [F.] = fim; [R] = reset.
  • SYN sem resposta = timeout (filtrado); RST = porta fechada (recusada).
