Problemas comuns de rede — e como resolver

Toda rede dá problema uma hora. A boa notícia: quase todo erro de rede deixa uma pista no terminal. Nesta página você encontra os erros mais comuns — com a mensagem exata que eles imprimem, a causa e o conserto. E o melhor: dá para provocar cada erro de propósito no terminal simulado abaixo para aprender a reconhecê-los.

Você vai aprender
  • O roteiro geral de diagnóstico: ping → dig → curl -v → traceroute → ss.
  • DNS NXDOMAIN e Could not resolve host: o nome não existe (ou o DNS falhou).
  • Connection refused: a máquina responde, mas a porta está fechada.
  • Timeout / host não responde: o caminho até a máquina está bloqueado ou ela está fora.
  • Porta em uso (Address already in use): outro processo já está na porta.

O roteiro de diagnóstico (sempre nesta ordem)

  1. ping exemplo.com — a máquina responde? (testa ICMP e a rota até ela)
  2. dig exemplo.com +short — o nome resolve para IP? (testa o DNS)
  3. curl -v https://exemplo.com — a conversa HTTP acontece? onde quebra? (DNS, TCP, TLS, status)
  4. traceroute exemplo.com — em qual salto o caminho para?
  5. ss -tlnp — e aqui na minha máquina, minhas portas estão como deveriam?

Regra de ouro: um erro em um passo não significa que os outros vão falhar — o ping pode falhar (ICMP bloqueado no firewall) e o site abrir normal no navegador.

1. DNS NXDOMAIN — "esse nome não existe"

Erro real: dig naoexiste.com → ;; ->>HEADER<<- opcode: QUERY, status: NXDOMAIN (e no nslookup: ** server can't find naoexiste.com: NXDOMAIN)

Causa: o domínio não está registrado no DNS (erro de digitação, domínio expirado, ou registro ainda propagando). Solução: confira a grafia; teste com outro DNS (dig @8.8.8.8 exemplo.com) para saber se o problema é o seu DNS local; se for seu domínio, veja o painel do registrador.

$ dig naoexiste.com
;; ->>HEADER<<- opcode: QUERY, status: NXDOMAIN, id: 4821
;; QUESTION SECTION:
;naoexiste.com.                 IN      A
;; Query time: 12 msec
;; SERVER: 192.168.1.1#53(192.168.1.1)

Missão: provoque o erro: rode dig naoexiste.com e veja NXDOMAIN no status.

2. Could not resolve host — curl/ping não acham o nome

Erro real: curl: (6) Could not resolve host: naoexiste.com · ping: cannot resolve naoexiste.com: Name or service not known · wget: unable to resolve host address

Causa: mesma do NXDOMAIN — o DNS não conseguiu traduzir o nome (nome errado, DNS fora do ar, ou /etc/resolv.conf sem servidor). Solução: teste o DNS em si (cat /etc/resolv.conf, dig @8.8.8.8 google.com +short); se o DNS local morreu, troque temporariamente para 8.8.8.8; se o nome estiver certo e mesmo assim falhar, pode ser o domínio fora do ar (confira com dig @8.8.8.8).

Missão: rode curl naoexiste.com e veja o erro curl: (6) Could not resolve host.

Missão: rode ping naoexiste.com e veja ping: cannot resolve naoexiste.com.

3. Connection refused — a porta está fechada

Erro real: curl: (7) Failed to connect to exemplo.com port 8080 after 2 ms: Connection refused · nc: connect to localhost 9999 port [tcp/*] failed: Connection refused

Causa: a máquina respondeu (a rede até ela está OK), mas ninguém está ouvindo naquela porta — o serviço desligou ou está em outra porta. Solução: verifique a porta certa (na máquina local: ss -tlnp; na remota: nc -zv HOST PORTA ou nmap HOST); se for seu servidor, suba o serviço (python3 -m http.server 8000) ou veja os logs dele.

Missão: teste uma porta fechada num host que responde: rode nc -zv exemplo.com 22 (o exemplo.com só abre 80 e 443) e veja o aviso de porta fechada.

4. Timeout — o host não responde (ou o caminho está bloqueado)

Erro real: ping: sendmsg: Operation not permitted / 100% packet loss · curl: (28) Connection timed out after 10001 ms · traceroute mostra * * * nos últimos saltos · dig: ;; connection timed out; no servers could be reached

Causa: o host está desligado, o firewall bloqueou o ICMP/porta no caminho, ou a rota quebrou num salto intermediário. Solução: rode traceroute para achar o último salto que responde (o problema está depois dele); teste de outra rede (4G do celular) para saber se é do seu lado; se for seu servidor, verifique se está ligado e o firewall (iptables -L).

$ ping -c 2 192.168.1.99
PING 192.168.1.99 (192.168.1.99) 56(84) bytes of data.
--- 192.168.1.99 ping statistics ---
2 packets transmitted, 0 received, 100% packet loss
$ traceroute exemplo.com
 1  192.168.1.1      2.1 ms  2.3 ms  2.0 ms
 2  189.50.10.1      8.4 ms  8.1 ms  8.9 ms
 3  * * *            « daqui para frente, ninguém responde

Missão: veja o caminho até um host: rode traceroute exemplo.com e conte os saltos (192.168.1.1 → … → 93.184.216.34).

5. Porta em uso — "Address already in use"

Erro real: python3 -m http.server 8000 rodado duas vezes → OSError: [Errno 98] Address already in use · Bind for 0.0.0.0:8080 failed: port is already allocated

Causa: outro processo já está ouvindo naquela porta. Solução: ache quem é com ss -tlnp | grep :8000 (a coluna Process mostra o nome e o PID); mate o processo antigo (Ctrl+C no terminal dele, ou kill PID) ou use outra porta (python3 -m http.server 8001).

Missão: rode ss -tlnp e veja quem está ocupando as portas 22 e 8000 (estado LISTEN + processo).

6. "O site não abre" — checklist completo

$ ping exemplo.com                  « 1. ICMP responde?
64 bytes from 93.184.216.34: icmp_seq=1 ttl=64 time=23.4 ms
$ dig exemplo.com +short            « 2. DNS traduz?
93.184.216.34
$ curl -v https://exemplo.com       « 3. HTTP chega? status?
* Connected to exemplo.com (93.184.216.34) port 443
< HTTP/2 200
$ traceroute exemplo.com            « 4. rota ok até o fim?
$ ss -tlnp                          « 5. e aqui dentro, minhas portas?

Interpretação rápida: falhou no 1 e no 2 → DNS ou digitação; falhou no 1 mas o 3 funciona → só ICMP bloqueado (normal); falhou no 3 com (6) → DNS; com (7) → porta fechada/firewall; com (28) → timeout; status 5xx → problema no servidor.

Resumo

  • NXDOMAIN / Could not resolve host = o nome não existe no DNS (teste com dig @8.8.8.8).
  • Connection refused = a máquina responde, mas a porta está fechada (veja ss -tlnp / nc -zv).
  • Timeout / 100% packet loss = ninguém responde no caminho (use traceroute para achar onde para).
  • Address already in use = porta ocupada por outro processo (ache com ss -tlnp).
  • Roteiro: ping → dig → curl -v → traceroute → ss.
