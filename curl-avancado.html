curl avançado — a chave inglesa das requisições

Na aula seu primeiro curl você fez requisições simples. Agora vamos ligar o modo completo do curl: as opções que mostram os headers, revelam a conversa inteira, mudam o método e mandam dados para APIs.

Você vai aprender
  • -i — resposta com headers + corpo.
  • -I — só o cabeçalho da resposta (rápido para testar).
  • -v — modo verboso: a conversa inteira, linha por linha.
  • -X METODO e -d 'dados' — mandar verbos e JSON para a API.
  • A tabela de opções úteis: -H, -L, -o, --max-time…

-i: corpo + cabeçalho

Sem opções, o curl mostra só o corpo. Com -i (include), os headers da resposta vêm antes:

$ curl -i https://api.exemplo.com/usuarios
HTTP/2 200
content-type: application/json
content-length: 87

[{"id":1,"nome":"Ana"},{"id":2,"nome":"Beto"},{"id":3,"nome":"Carla"}]

-I: só o cabeçalho

Com -I (head), o servidor devolve somente os headers, sem o corpo — ótimo para testar se um site está no ar e qual status devolve:

$ curl -I https://exemplo.com
HTTP/2 200
server: nginx/1.25.3
content-type: text/html; charset=UTF-8
strict-transport-security: max-age=31536000

Missão: teste o status de um site sem baixar o corpo: curl -I https://exemplo.com

-v: a conversa inteira

Com -v (verbose), o curl conta tudo o que acontece:

$ curl -v -X POST -d '{"nome":"Ana"}' https://api.exemplo.com/usuarios
* Trying 93.184.216.35:443...          « tenta abrir a conexão TCP na porta 443
* Connected to api.exemplo.com (93.184.216.35) port 443   « conectou!
> POST api.exemplo.com/usuarios HTTP/1.1   « o que o curl ENVIOU (linha de requisição)
> Host: api.exemplo.com
> User-Agent: curl/8.5.0
> Accept: */*
> Content-Type: application/json     « o -d avisou que o corpo é JSON
> Content-Length: 15
>
[{"id":1,"nome":"Ana"},{"id":2,"nome":"Beto"},{"id":3,"nome":"Carla"}]   « corpo da resposta
* Connection #0 to host api.exemplo.com left intact
  • Linhas com * = o progresso da conexão (resolver o nome, abrir o TCP).
  • Linhas com > = o que o curl enviou (requisição).
  • No curl real, as linhas com < mostram a resposta; no simulador, a resposta aparece depois do > em branco.

Missão: veja a conexão acontecer passo a passo: curl -v https://exemplo.com — procure a linha * Connected to …

Missão: mande um POST com JSON e veja o verbo na linha enviada: curl -v -X POST -d '{"nome":"Ana"}' https://api.exemplo.com/usuarios

-X e -d: falar com APIs

Juntos, -X e -d são como preencher um formulário pela linha de comando. Sem -X, o curl faz GET; com -d, vira POST por padrão:

$ curl -i -X PUT -d '{"nome":"Beto"}' https://api.exemplo.com/usuarios
HTTP/2 200
content-type: application/json
content-length: 87

[{"id":1,"nome":"Ana"},{"id":2,"nome":"Beto"},{"id":3,"nome":"Carla"}]
$ curl -i -X DELETE https://api.exemplo.com/usuarios/999
HTTP/2 404
content-type: application/json

{"erro":"usuário não encontrado"}

Atenção às aspas: JSON usa aspas duplas ("nome"), então envolva o dado em aspas simples: -d '{"nome":"Ana"}'. Se o JSON tiver espaços, as aspas são obrigatórias — senão o shell quebra o comando no meio.

Missão: baixe só o corpo da resposta (sem headers) e ache a Ana no JSON: curl https://api.exemplo.com/usuarios

Missão: confirme que a API responde JSON vendo o header: curl -i https://api.exemplo.com/usuarios

Tabela de opções úteis

OpçãoO que faz
-iMostra os headers da resposta junto com o corpo.
-IMostra só os headers (pedido HEAD).
-vModo verboso: mostra a conversa inteira.
-X METODOEscolhe o método: POST, PUT, PATCH, DELETE…
-d 'dados'Envia o corpo da requisição (vira POST se não houver -X).
-H 'Header: valor'Acrescenta um header (ex.: -H 'Authorization: Bearer xyz').
-LSegue redirecionamentos (301/302) automaticamente.
-o arquivoSalva a resposta num arquivo (tipo o wget).
--max-time NDesiste se passar de N segundos (evita travar).
-sSilencioso: não mostra a barra de progresso.
Nunca use -k em produção: ela faz o curl ignorar erros de certificado HTTPS (desliga a segurança do cadeado — aula HTTPS/TLS). Só em testes locais, com certificado autoassinado.

O que faz o curl -v?

Resumo

  • curl URL = GET só com o corpo; -i = + headers da resposta; -I = só headers; -v = conversa inteira.
  • -X METODO troca o verbo; -d '…' manda o corpo (JSON entre aspas simples!).
  • Na API fictícia: https://api.exemplo.com/usuarios lista usuários (200) e /usuarios/999 devolve 404.
  • Para APIs reais, você ainda vai usar -H 'Authorization: …' (token) e -L (redirecionamentos).
