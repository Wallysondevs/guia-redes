DHCP: pegar IP automático

Quando o notebook da Ana entra no Wi-Fi, ele não sabe nem o próprio IP. O DHCP (Dynamic Host Configuration Protocol) é o protocolo que resolve isso: é como chegar numa festa e o anfitrião entregar um crachá com número (o IP 192.168.1.50), dizer a porta de saída do salão (o gateway 192.168.1.1) e o telefone da recepção (os DNS 192.168.1.1 e 8.8.8.8). Você usa o crachá durante a festa — e o devolve quando vai embora.

Você vai aprender
  • O ciclo DORA: Discover → Offer → Request → Acknowledge.
  • O que o DHCP entrega além do IP: máscara, gateway padrão, DNS, lease (tempo de validade).
  • O servidor DHCP geralmente é o próprio roteador (192.168.1.1).
  • O que acontece quando o DHCP falha: IP 169.254.x.x (APIPA).
  • Como ver o resultado: ip route (linha com proto dhcp) e cat /etc/resolv.conf.

O ciclo DORA, passo a passo

Quando o computador liga na rede, acontece uma conversa de 4 mensagens (todas em broadcast/UDP porta 67–68):

1. Discover
O computador grita na rede local: "Tem servidor DHCP aqui? Preciso de um IP!" (origem ainda é 0.0.0.0, porque ele não tem IP).
2. Offer
O servidor DHCP (o roteador) responde: "Posso te dar o 192.168.1.50, com máscara /24, gateway 192.168.1.1 e DNS 192.168.1.1, 8.8.8.8, válido por 24h".
3. Request
O computador responde: "Aceito o 192.168.1.50!" (pode haver vários servidores oferecendo; ele escolhe um).
4. Acknowledge (ACK)
O servidor confirma: "Confirmado, o 192.168.1.50 é seu pelas próximas 24 horas". Pronto — o computador já pode usar a rede.

O que o DHCP entrega (o "crachá completo")

InformaçãoNa rede da AnaPara que serve
Endereço IP + máscara192.168.1.50/24O endereço da máquina e o tamanho da rede local
Gateway padrão192.168.1.1A "porta de saída" para a internet (próxima aula)
Servidores DNS192.168.1.1, 8.8.8.8Quem traduz nomes em IPs
Lease (tempo de validade)24 horas (exemplo)Depois desse prazo, o computador precisa renovar o "aluguel" do IP
Domínio de buscalocaldomainSufixo usado ao resolver nomes curtos

O lease é importante: se a Ana desligar o notebook, depois de 24h o roteador pode emprestar o 192.168.1.50 para outro dispositivo. É por isso que o IP do celular "muda de vez em quando".

Como ver o resultado no computador

A rota padrão mostra que ela veio via DHCP, e o /etc/resolv.conf mostra os DNS recebidos:

$ ip route
default via 192.168.1.1 dev eth0 proto dhcp metric 100     « gateway entregue pelo DHCP
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.50 metric 100
$ cat /etc/resolv.conf
nameserver 192.168.1.1
nameserver 8.8.8.8
search localdomain

Missão: rode ip route e encontre proto dhcp na linha do gateway — prova de que o 192.168.1.1 (e o IP da máquina) vieram do DHCP.

Missão: rode cat /etc/resolv.conf e veja os servidores DNS que o DHCP entregou: 192.168.1.1 e 8.8.8.8.

Quando o DHCP falha

Se o computador não consegue falar com nenhum servidor DHCP, ele inventa um endereço próprio na faixa 169.254.0.0/16 (APIPA) — é o equivalente a chegar na festa e ninguém ter crachá para você. Resultado: ele fala só com outros que também estão nessa faixa provisória; a internet não funciona. Ver um IP 169.254.x.x no ip addr é o clássico sinal de "o DHCP não respondeu" (roteador desligado, cabo solto, Wi-Fi sem senha certa…).

IP fixo (manual) também existe

Nada obriga a usar DHCP: dá para configurar o IP na mão (192.168.1.50, máscara, gateway, DNS). É comum em servidores — mas se configurar errado (IP fora da faixa, gateway esquecido), a máquina fica isolada. Em casa, deixe no automático.

Resumo

  • DHCP entrega automaticamente: IP + máscara, gateway padrão, DNS e o lease (tempo de validade).
  • O ciclo DORA: Discover → Offer → Request → Acknowledge (UDP 67/68, geralmente no roteador).
  • Veja o resultado com ip route (proto dhcp) e cat /etc/resolv.conf (nameservers).
  • Sem DHCP: IP provisório 169.254.x.x (APIPA) e internet fora do ar.
