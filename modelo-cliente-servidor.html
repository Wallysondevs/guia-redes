Modelo cliente-servidor: a dupla de toda requisição

Nada na internet acontece "sozinho": toda conversa na rede tem sempre dois lados — um que pede (o cliente) e um que responde (o servidor). Quando você abre um site, o seu navegador é o cliente e o site é o servidor. Nesta aula, a analogia do restaurante deixa isso obvious.

Você vai aprender
  • O que é um cliente: navegador, curl, app de celular — qualquer programa que inicia o pedido.
  • O que é um servidor: um programa que fica esperando pedidos numa porta (ex.: 80, 443) e responde.
  • A analogia do restaurante: pedido no cardápio = requisição, prato pronto = resposta.
  • Que cliente e servidor são papéis, não máquinas fixas: seu notebook pode ser servidor também.
  • Seu primeiro curl no simulador: pedir uma página para um servidor.

A analogia do restaurante

Imagine um restaurante:

  • Você (cliente) olha o cardápio e faz um pedido: "quero o prato 12, por favor" — essa frase é a requisição (em rede: GET /pratos/12 HTTP/1.1).
  • A cozinha (servidor) está o dia inteiro esperando pedidos. Ela recebe o seu, prepara e devolve o prato — essa é a resposta (em rede: HTTP/1.1 200 OK + a página).
  • Se você pedir um prato que não existe, a cozinha responde "não temos" — em rede é o erro 404 Not Found.
  • Se a cozinha está fechada, ninguém atende — em rede é "connection refused" (conexão recusada).

Toda requisição na internet funciona assim: cliente pede, servidor responde. Até um WhatsApp: seu app (cliente) pede a mensagem ao servidor do WhatsApp, que responde com a mensagem.

Quem é o cliente e quem é o servidor

ClienteServidor
O que fazInicia a conversa: faz o pedidoEspera parado numa porta e responde aos pedidos
ExemplosNavegador (Chrome, Firefox), curl, wget, app de celular, pingSite (nginx, Apache), API, servidor de e-mail, servidor SSH (sshd)

EndereçoQualquer IP (o seu: 192.168.1.50)Um IP + uma porta (ex.: 93.184.216.34 na porta 443)
Cliente e servidor são papéis, não máquinas.

O seu notebook hoje é cliente quando você abre um site — mas ele também pode ser servidor: a Ana roda um servidorzinho de páginas nele (python3 http.server na porta 8000, que você vai ver com ss -tlnp). Um mesmo computador pode ser os dois ao mesmo tempo.

A conversa na prática: um pedido de página

Quando o navegador da Ana abre exemplo.com, a conversa é mais ou menos esta (simplificada):

Cliente →
"GET / HTTP/1.1" — quero a página inicial
Cliente →
"Host: exemplo.com" — deste site, por favor
Servidor →
"HTTP/1.1 200 OK" — achei, segue a página
Servidor →
Cabeçalhos (tipo de conteúdo, tamanho…) + o HTML da página

Com o curl dá para ver essa conversa inteira pela linha de comando. O -i mostra os cabeçalhos da resposta junto com o corpo:

$ curl -i exemplo.com
HTTP/1.1 200 OK
Server: nginx/1.25.3
Content-Type: text/html; charset=UTF-8
Content-Length: 1256
Connection: keep-alive

<html><head><title>Exemplo</title></head><body><h1>Exemplo.com</h1>…</body></html>

Missão: digite curl -i exemplo.com e aperte Enter. Você está fazendo o papel de cliente: pedindo a página para o servidor e vendo a resposta 200 OK com os cabeçalhos.

Resumo

  • Toda conversa na rede é cliente-servidor: um lado pede (requisição), o outro responde (resposta).
  • Cliente = navegador, curl, app. Servidor = programa escutando numa porta (80/443 para sites).
  • Os papéis são flexíveis: seu próprio computador pode ser servidor (a Ana roda um na porta 8000).
  • curl -i exemplo.com mostra a conversa inteira: status 200 OK, cabeçalhos e o corpo da página.
