Códigos de status HTTP (cola)

Toda resposta HTTP começa com uma linha de status: HTTP/1.1 200 OK. O número de 3 dígitos diz em qual classe a resposta caiu — e a primeira letra da classe já conta a história: 2xx = deu certo, 3xx = mudou de lugar, 4xx = você pediu errado, 5xx = o servidor errou. Pense como a resposta do balconista: "aqui está" (2xx), "mudamos de endereço" (3xx), "você não pode pedir isso" (4xx), "nossa cozinha está com problema" (5xx).

Você vai aprender
  • A regra das classes: 1xx informativo, 2xx sucesso, 3xx redirecionamento, 4xx erro do cliente, 5xx erro do servidor.
  • Os códigos que aparecem todo dia: 200, 201, 204, 301, 302, 304, 400, 401, 403, 404, 405, 408, 429, 500, 502, 503, 504.
  • A diferença entre 301 e 308, e entre 401 e 403.
  • Como ver o status na prática: curl -i (a 1ª linha da resposta).

2xx — sucesso ("deu certo, aqui está")

CódigoNomeQuando acontece
200OKO pedido padrão funcionou: GET trouxe a página, POST funcionou. É o código que você mais vai ver.
201CreatedUm POST criou um recurso novo com sucesso (ex.: cadastrou um usuário) — a resposta traz o recurso criado e, às vezes, um header Location com a URL dele.
204No ContentDeu certo, mas não tem corpo na resposta (comum em DELETE que deu certo).
206Partial ContentO servidor entregou só um pedaço do arquivo (Range) — é assim que o download retoma de onde parou e que o vídeo "pula" para outro trecho.
$ curl -i http://exemplo.com
HTTP/1.1 200 OK
Server: nginx/1.25.3
Content-Type: text/html; charset=UTF-8

<html>…</html>

3xx — redirecionamento ("mudou de endereço")

CódigoNomeQuando acontece / detalhe
301Moved PermanentlyA URL mudou para sempre; o navegador guarda em cache. Ex.: http:// → https://, ou domínio antigo → novo.
302FoundRedirecionamento temporário (o destino pode mudar depois). Ex.: após login, volta para a página que você queria.
304Not Modified"Sua cópia em cache ainda vale" — o servidor não manda o arquivo de novo (economia de banda; vem com o header ETag/Cache-Control).
307 / 308Temporary / Permanent RedirectIguais ao 302/301, mas mantêm o método (um POST redirecionado continua POST — o 302 histórico mudava para GET).

O redirecionamento vem sempre com o header Location: https://… dizendo para onde ir. No curl, siga com -L.

4xx — erro do cliente ("você pediu errado")

CódigoNomeCausa típica
400Bad RequestA requisição está malformada (JSON quebrado, header inválido).
401UnauthorizedNão autenticado: faltou token/senha. O servidor manda WWW-Authenticate dizendo como logar.
403ForbiddenAutenticado, mas sem permissão para aquele recurso (diferente do 401: aqui você entrou, mas não pode).
404Not FoundA URL não existe no servidor. A conexão funcionou — o recurso é que não foi achado (comum em API: /usuarios/999).
405Method Not AllowedO método não é aceito naquela URL (ex.: fez POST numa rota só de GET).
408Request TimeoutVocê demorou demais para mandar a requisição completa.
429Too Many RequestsVocê fez pedidos demais em pouco tempo — o servidor pediu um limite (rate limit).

Missão: provoque um 404 de verdade: rode curl -i https://api.exemplo.com/usuarios/999 e veja HTTP/2 404 + o JSON de erro.

$ curl -i http://exemplo.com/nao-existe
HTTP/1.1 404 Not Found
Server: nginx/1.25.3
Content-Type: text/html

<html><body><h1>404 Not Found</h1></body></html>

5xx — erro do servidor ("nossa cozinha errou")

CódigoNomeCausa típica
500Internal Server ErrorErro genérico no servidor (bug no código, exceção não tratada). É problema do dono do site, não seu.
502Bad GatewayUm proxy/gateway (ex.: Nginx na frente) não conseguiu falar com o servidor de trás.
503Service UnavailableServidor sobrecarregado ou em manutenção — tente de novo mais tarde (às vezes manda Retry-After).
504Gateway TimeoutO gateway esperou demais a resposta do servidor de trás e desistiu.

1xx — informativo (raro no dia a dia)

CódigoNomeUso
100Continue"Pode mandar o resto" — usado antes de enviar um corpo grande.
101Switching ProtocolsTroca de protocolo na mesma conexão — é assim que o WebSocket começa (aula WebSockets).

Como ler o status na prática

$ curl -i https://api.exemplo.com/usuarios
HTTP/2 200                 « primeira linha = versão + código + nome
content-type: application/json

[{…}]                     « corpo vem depois de uma linha em branco

Regra de bolso: 2xx segue em frente; 3xx siga o Location (ou use curl -L); 4xx olhe o seu pedido (URL, método, autenticação); 5xx é problema do servidor — recarregue mais tarde e, se persistir, avise o dono.

Missão: rode curl -i https://api.exemplo.com/usuarios e confirme o HTTP/2 200 na primeira linha.
