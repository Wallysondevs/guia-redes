ICMP: o protocolo por trás do ping e do traceroute

Nem todo pacote na internet leva dados de usuário. Às vezes a rede precisa mandar só um cartão-postal de controle: "você está aí?", "essa rua não existe", "acabou o tempo". Quem faz esse serviço é o ICMP (Internet Control Message Protocol) — o "zelador" da camada de internet (camada 3 do TCP/IP, a mesma do IP). O ping e o traceroute são, no fundo, ICMP.

Você vai aprender
  • O que é o ICMP e por que ele não leva dados de aplicação;
  • Os tipos de mensagem que você vai encontrar: Echo (ping), Time Exceeded (traceroute), Destination Unreachable;
  • Como o ping funciona passo a passo (Echo Request → Echo Reply);
  • Como o traceroute usa o TTL para revelar cada roteador do caminho;
  • Por que "ping não responde" não significa "site fora do ar".

O que é o ICMP

O IP é como o correio: ele entrega pacotes, mas não avisa se deu erro. O ICMP anda junto com o IP (é um protocolo da mesma camada, número 1 no campo "protocolo" do header IP) e existe para reportar erros e trocar mensagens de controle. Ele não cria conexão — cada mensagem ICMP vai dentro de um pacote IP comum.

Tipo ICMPNomePara que serveComando que usa
8Echo Request"Você está aí?"ping
0Echo Reply"Estou!" (com o tempo de ida e volta)
11Time Exceeded"O TTL acabou no meu roteador"traceroute
3Destination Unreachable"Não consegui entregar: rede/porta/host inacessível"aparece em erros de rota
5Redirect"Use outro gateway, esse é melhor"roteadores avisando entre si

Como o ping funciona

O ping manda um pacote ICMP do tipo Echo Request (tipo 8) para o destino. Se o destino estiver ligado e aceitando ICMP, ele responde com Echo Reply (tipo 0). O ping mede o tempo entre o envio e a resposta — o time=23.4 ms:

$ ping exemplo.com
PING exemplo.com (93.184.216.34) 56(84) bytes of data.
64 bytes from 93.184.216.34: icmp_seq=1 ttl=64 time=23.4 ms
64 bytes from 93.184.216.34: icmp_seq=2 ttl=64 time=22.9 ms

--- exemplo.com ping statistics ---
2 packets transmitted, 2 received, 0% packet loss

Cada linha 64 bytes from … é um Echo Reply. O icmp_seq é o número do pacote (para saber se perdeu algum no caminho) e o ttl=64 mostra quantos roteadores ainda restavam quando a resposta passou — dá para ter uma ideia da distância.

Missão: rode ping exemplo.com e veja as respostas 64 bytes from …. Experimente também ping -c 2 192.168.1.1 (o gateway da rede da Ana, resposta em milissegundos bem menores).

Como o traceroute funciona (o truque do TTL)

Lembra do TTL da aula de encapsulamento? Cada pacote IP nasce com um TTL e cada roteador desconta 1; se zerar, o roteador descarta o pacote e manda um ICMP Time Exceeded de volta. O traceroute usa isso como uma sonda: manda pacotes com TTL 1, depois 2, depois 3… e cada roteador do caminho se "denuncia" na resposta:

$ traceroute exemplo.com
traceroute to exemplo.com (93.184.216.34), 30 hops max, 60 byte packets
 1  192.168.1.1 (192.168.1.1)  2.145 ms  2.301 ms  2.112 ms
 2  189.50.10.1 (189.50.10.1)  8.532 ms  8.401 ms  8.610 ms
 3  200.147.67.142 (200.147.67.142)  15.220 ms  15.104 ms  15.388 ms
 4  93.184.216.34 (93.184.216.34)  23.410 ms  23.201 ms  23.577 ms

Cada linha é um salto (hop) — um roteador no caminho — com 3 medições de tempo. O primeiro salto (192.168.1.1) é o gateway da Ana; o último é o próprio destino. É assim que a aula Como o pacote viaja mostra o caminho na prática.

Missão: rode traceroute exemplo.com e veja cada salto até o destino. Compare com traceroute google.com — caminhos diferentes, redes diferentes.

Ping que não responde ≠ site fora do ar

Muitos servidores e firewalls bloqueiam ICMP de propósito (para não serem descobertos por scans e para não gastar CPU com flood). Nesse caso o ping dá "timeout", mas o site abre normalmente no navegador — porque o site usa TCP/porta 443, não ICMP. Para testar se um serviço está no ar, teste a porta certa: nc -zv exemplo.com 443 ou curl -i https://exemplo.com.

ICMP também é usado em ataques

Como o ICMP não tem autenticação, dá para mandar um flood de Echo Requests (ping flood) para sobrecarregar alguém — um tipo clássico de ataque de negação de serviço (aula DDoS). Por isso muitos sites e operadoras limitam a taxa de ICMP: se você mandar 1000 pings por segundo, a maioria é descartada silenciosamente.

Resumo

  • ICMP é o protocolo de controle e erro da camada de internet — anda dentro de pacotes IP, sem conexão.
  • ping = Echo Request (8) → Echo Reply (0), e mede o tempo de ida e volta.
  • traceroute manda pacotes com TTL 1, 2, 3… e cada roteador responde Time Exceeded (11), revelando o caminho.
  • ICMP bloqueado não significa host desligado — teste a porta do serviço (nc -zv, curl).
  • ICMP pode ser abusado (ping flood) — por isso é comum limitar a taxa de respostas.
