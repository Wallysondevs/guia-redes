Anatomia de uma URL

Uma URL é o endereço completo do pedido: diz como falar (protocolo), com quem falar (domínio), em qual sala (porta), o que você quer (caminho), com quais parâmetros (query) e em que parte da página (fragmento). Vamos abrir essa URL peça por peça:

Anatomia da URL de exemplo 
https://exemplo.com:443/produtos?busca=rede&pagina=2#resultados
Você vai aprender
  • Cada peça de uma URL: https, exemplo.com, :443, /produtos, ?busca=rede&pagina=2, #resultados.
  • Portas implícitas: HTTP usa 80, HTTPS usa 443 — por isso você nunca as digita.
  • A diferença entre caminho (path), query (?chave=valor) e fragmento (#).
  • Ver na prática com curl -i: HTTP na porta 80 vs HTTPS na porta 443.

Peça por peça

https
O protocolo (scheme): como a conversa vai acontecer. https = HTTP + criptografia TLS. Outros: http, ftp.
://
Separador depois do protocolo.
exemplo.com
O domínio (host): o nome do servidor. O DNS traduz esse nome para um IP (próxima aula). Pode virar IP direto: https://93.184.216.34.
:443
A porta. Quase sempre omitida porque cada protocolo tem sua porta padrão: HTTP = 80, HTTPS = 443. Escrever :443 é o mesmo que não escrever nada.
/produtos
O caminho (path): qual página/recurso dentro do servidor — como o corredor e a porta do apartamento.
?busca=rede&pagina=2
Os parâmetros de consulta (query string): pares chave=valor separados por &, depois do ?. É o bilhete com detalhes do pedido ("procuro 'rede', página 2").
#resultados
O fragmento: âncora dentro da página (rola até a seção "resultados"). Ele não vai para o servidor — só o navegador usa.

Porta escondida na URL

Você nunca vê :80 nem :443 nos sites, porque o navegador completa sozinho:

URLPorta usada (implícita)O que acontece
http://exemplo.com80Cliente bate na sala 80 do servidor (HTTP puro)
https://exemplo.com443Cliente bate na sala 443 (HTTP + TLS, criptografado)
https://exemplo.com:84438443Porta explícita: bate na sala 8443, não na padrão

Na prática: HTTP vs HTTPS no terminal

Compare as respostas: o HTTP responde HTTP/1.1 200 OK (porta 80); o HTTPS responde HTTP/2 200 (porta 443, criptografado, e com o cabeçalho strict-transport-security que obriga o navegador a sempre usar HTTPS):

$ curl -i http://exemplo.com
HTTP/1.1 200 OK
Server: nginx/1.25.3
Content-Type: text/html; charset=UTF-8

<html>…</html>
$ curl -i https://exemplo.com
HTTP/2 200
server: nginx/1.25.3
content-type: text/html; charset=UTF-8
strict-transport-security: max-age=31536000

<html>…</html>

Missão: digite curl -i https://exemplo.com e aperte Enter. A primeira linha da resposta (HTTP/2 200) mostra que a conversa aconteceu na porta 443, com criptografia.

Resumo

  • URL completa: protocolo://domínio:porta/caminho?query#fragmento.
  • https = protocolo seguro; exemplo.com = domínio (o DNS traduz para IP); porta implícita 443 (HTTPS) ou 80 (HTTP).
  • /caminho = o recurso pedido; ?chave=valor = parâmetros enviados ao servidor; #ancora = só o navegador usa.
  • curl -i deixa visível a diferença: HTTP responde HTTP/1.1 200 OK, HTTPS responde HTTP/2 200.
