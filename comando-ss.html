Comando ss -tlnp: quais portas estão abertas

Sua máquina pode ser servidora também: um programa nela fica escutando numa porta, esperando pedidos. O comando ss -tlnp lista exatamente isso — as salas abertas no seu prédio. Na máquina da Ana há duas: o SSH (22) e um servidorzinho de páginas (8000).

Você vai aprender
  • O que o ss mostra: as conexões de rede da máquina, especialmente as que escutam (LISTEN).
  • A anatomia das opções: -t (TCP), -l (só escuta), -n (números, sem traduzir), -p (mostra o processo).
  • Ler as colunas: Netid, State, Local Address:Port, Peer e Process.
  • 0.0.0.0 = aceita conexões de qualquer lugar; 127.0.0.1 = só da própria máquina.
  • O primo antigo netstat -tlnp, que faz a mesma coisa.
  • Testar a porta aberta de verdade com nc -zv localhost 8000.

A anatomia das opções

ss
"Socket Statistics": mostra as conexões (sockets) da máquina.
-t
Só conexões TCP (as de UDP serían -u).
-l
listening: só as portas que estão escutando, esperando pedido (LISTEN).
-n
numeric: mostra números (22, 8000) em vez de traduzir para nomes de serviço (ssh, http-alt).
-p
process: mostra qual processo abriu a porta (ex.: sshd, python3).

A saída na máquina da Ana

$ ss -tlnp
Netid State  Recv-Q Send-Q Local Address:Port  Peer Address:Port Process
TCP   LISTEN 0      128    0.0.0.0:22          0.0.0.0:*     users:(("sshd",4321))
TCP   LISTEN 0      128    0.0.0.0:8000        0.0.0.0:*     users:(("python3",8765))

Lendo a tabela:

  • TCP LISTEN — protocolo TCP, estado escutando (esperando conexão).
  • 0.0.0.0:22 — escuta na porta 22 em 0.0.0.0, ou seja, aceita conexões de qualquer IP (de fora também).
  • users:(("sshd",4321)) — o processo sshd (servidor SSH) foi quem abriu a porta 22.
  • 0.0.0.0:8000 com python3 — é o python3 http.server que a Ana ligou: um servidor de páginas na porta 8000.
  • Peer 0.0.0.0:* — ainda não tem ninguém conectado (quando alguém conectar, aparece o IP dele aqui).

Missão: digite ss -tlnp e aperte Enter. Devem aparecer duas linhas LISTEN: as portas 22 (sshd) e 8000 (python3) do notebook da Ana.

0.0.0.0 vs 127.0.0.1: quem pode bater na porta

Endereço de escutaSignificadoExemplo
0.0.0.0:8000Aceita conexões de qualquer lugar (sua rede e a internet, se passar pelo roteador)O servidorzinho da Ana na 8000
127.0.0.1:8000Aceita só conexões da própria máquina (mais seguro)Um banco de dados local de desenvolvimento

Testando a porta aberta: nc -zv localhost 8000

Depois de ver a porta 8000 escutando, dá para bater nela de verdade com o netcat:

$ nc -zv localhost 8000
Connection to localhost 8000 port [tcp/*] succeeded!

Missão: digite nc -zv localhost 8000 e aperte Enter. Como a porta 8000 está aberta (você viu no ss), a resposta deve ser … succeeded!.

O primo antigo: netstat -tlnp

Muitos tutoriais usam netstat -tlnp — faz exatamente a mesma coisa que o ss -tlnp (hoje o ss é o recomendado, mais rápido):

$ netstat -tlnp
Netid State  Recv-Q Send-Q Local Address:Port  Peer Address:Port Process
TCP   LISTEN 0      128    0.0.0.0:22          0.0.0.0:*     users:(("sshd",4321))
TCP   LISTEN 0      128    0.0.0.0:8000        0.0.0.0:*     users:(("python3",8765))

Resumo

  • ss -tlnp = TCP + listening + numérico + processo: a lista das portas que a máquina está escutando.
  • Na máquina da Ana: 0.0.0.0:22 (sshd) e 0.0.0.0:8000 (python3 http.server).
  • 0.0.0.0 aceita de qualquer lugar; 127.0.0.1 só local.
  • netstat -tlnp é o equivalente antigo; nc -zv HOST PORTA testa se a sala está aberta.
