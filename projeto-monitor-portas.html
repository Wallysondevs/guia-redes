Projeto 5 — monitorar portas com ss + script

Uma máquina ligada em rede é como uma casa com várias portas: algumas estão abertas e ouvindo (um servidor esperando conexões), outras fechadas. Saber quais portas estão abertas no seu computador é essencial para segurança — porta aberta demais é porta de entrada para invasores. Neste projeto a Ana vai listar as portas do notebook, testar uma a uma e deixar um monitor rodando ao vivo.

Você vai aprender
  • ss -tlnp: listar portas TCP em escuta (LISTEN) com o processo responsável.
  • netstat -tlnp: o mesmo, no formato antigo (ainda existe em muitos sistemas).
  • nc -zv localhost 8000: testar se uma porta abre, sem mandar dados.
  • nmap localhost: escanear as portas do próprio host.
  • Um script com watch que atualiza a lista sozinha a cada 2 segundos.

Passo 1 — listar as portas em escuta: ss -tlnp

O comando ss (socket statistics) mostra os sockets — as "pontas" das conexões. As opções do dia a dia:

-t
Só sockets TCP.
-u
Só sockets UDP (ex.: ss -ulnp mostra o DNS em UDP 53).
-l
Só os que estão escutando (LISTEN) — os servidores esperando conexão.
-n
Mostra números (portas/IPs) em vez de nomes — mais rápido e sem consulta DNS reversa.
-p
Mostra o processo dono do socket (precisa de permissão; por isso o sudo em alguns casos).
$ ss -tlnp
Netid State  Recv-Q Send-Q Local Address:Port  Peer Address:Port Process
TCP   LISTEN 0      128    0.0.0.0:22           0.0.0.0:*     users:(("sshd",1012))
TCP   LISTEN 0      128    0.0.0.0:8000         0.0.0.0:*     users:(("python3",2031))

Tradução: o notebook tem a porta 22 aberta (o servidor SSH, para acesso remoto) e a porta 8000 (o site do projeto 1). 0.0.0.0:22 significa "ouvindo em todos os IPs da máquina" — se fosse 127.0.0.1:8000, só o próprio computador alcançaria.

Missão: rode ss -tlnp e ache as portas em LISTEN (22 do sshd e 8000 do python3).

Passo 2 — testar uma porta específica: nc -zv

Quer saber se a porta 8000 responde agora, sem mandar requisição HTTP? O nc (netcat) é o "canivete suisse" das portas: com -z ele só escaneia, com -v ele fala o resultado:

$ nc -zv localhost 8000
Connection to localhost 8000 port [tcp/*] succeeded!
$ nc -zv localhost 9999
nc: connect to localhost 9999 port [tcp/*] failed: Connection refused

Missão: rode nc -zv localhost 8000 e veja succeeded! — a porta do site está aberta. Depois teste nc -zv localhost 9999 (porta fechada).

Passo 3 — escanear o próprio host: nmap localhost

O nmap é a ferramenta clássica de scan de portas (aula scan de portas — só no que é seu):

$ nmap localhost
Nmap scan report for localhost (127.0.0.1)
Host is up (0.000030s latency).
PORT     STATE  SERVICE
22/tcp   open   ssh
8000/tcp open   http-alt

Nmap done: 1 IP address (1 host up) scanned in 0.08 seconds

Missão: rode nmap localhost e veja o relatório de portas abertas do próprio notebook.

Ética e lei: só rode nmap em máquinas suas ou com autorização escrita. Escanear a rede do vizinho ou de uma empresa sem permissão é crime (no Brasil, invasão de dispositivo — art. 154-A do Código Penal). Use essa ferramenta para auditar a sua própria rede.

Passo 4 — monitor ao vivo com watch + script

Em vez de rodar ss toda hora, deixe um script vigiando. Salve o arquivo abaixo e rode com o watch, que re-executa o comando a cada 2 segundos e limpa a tela:

~/monitor-portas.sh
#!/bin/bash
# Mostra as portas TCP em escuta e marca as porta 22/8000
ss -tlnp | grep -E 'LISTEN|Netid' | \
  sed -e 's/:22 /:22 (ssh) /' -e 's/:8000 /:8000 (site) /'
$ chmod +x ~/monitor-portas.sh
$ watch -n 2 ~/monitor-portas.sh
Every 2.0s: /home/ana/monitor-portas.sh          notebook

Netid State  Recv-Q Send-Q Local Address:Port  Peer Address:Port Process
TCP   LISTEN 0      128    0.0.0.0:22 (ssh)     0.0.0.0:*     users:(("sshd",1012))
TCP   LISTEN 0      128    0.0.0.0:8000 (site)  0.0.0.0:*     users:(("python3",2031))

Na máquina real dá para ir além: watch -n 1 'ss -tlnp' puro já funciona; ou um laço com while true; do clear; ss -tlnp; sleep 2; done. Para registrar em arquivo (log de auditoria): while true; do ss -tlnp; date; sleep 60; done >> ~/portas.log &.

Missão: rode ss -tlnp de novo e ache 0.0.0.0:8000 — essa é a porta do site do projeto 1, aberta em todos os IPs da máquina.

Resumo do projeto

  • ss -tlnp = portas TCP em LISTEN + processo dono; netstat -tlnp é o equivalente antigo.
  • nc -zv HOST PORTA testa se a porta abre na hora (succeeded! / refused).
  • nmap localhost escaneia o próprio host — use só no que é seu.
  • watch -n 2 script.sh vira o comando num monitor ao vivo.
