Comando curl a fundo

O curl é o canivete suíço para falar HTTP pela linha de comando. Nesta aula você conhece as opções que mais usa no dia a dia — -i, -I, -v, -X, -d — e vê cada uma funcionando no simulador, inclusive os erros reais.

Você vai aprender
  • A anatomia: curl [OPÇÕES] URL.
  • -i (cabeçalhos + corpo), -I (só cabeçalhos), -v (a conversa inteira, estilo debug).
  • -X POST -d '…': enviar dados (JSON) para uma API.
  • Os erros reais: Could not resolve host (DNS) e 404 Not Found (recurso inexistente).
  • Ler a saída do -v: * Trying, * Connected, > GET ….

Anatomia do comando

curl
O programa: cliente HTTP de linha de comando.
-i
include: imprime os cabeçalhos da resposta antes do corpo.
-X GET
request: o método HTTP (GET é o padrão; aqui só explicitando).
https://exemplo.com
A URL: protocolo + domínio + caminho. Sem protocolo, assume http://.

-v: a conversa inteira (modo debug)

Com -v, o curl conta tudo o que aconteceu: qual IP o DNS devolveu, em qual porta conectou e o pedido enviado:

$ curl -v exemplo.com
* Trying 93.184.216.34:80...
* Connected to exemplo.com (93.184.216.34) port 80
> GET exemplo.com HTTP/1.1
> Host: exemplo.com
> User-Agent: curl/8.5.0
> Accept: */*
>
HTTP/1.1 200 OK
Server: nginx/1.25.3
…
* Connection #0 to host exemplo.com left intact

As linhas com * são do próprio curl (diagnóstico); as com > são o pedido enviado; o resto é a resposta do servidor.

Missão: digite curl -v exemplo.com e aperte Enter. Procure a linha * Connected to exemplo.com (93.184.216.34) port 80 — a conexão aconteceu.

POST com JSON: enviar dados para uma API

APIs aceitam dados em JSON. O comando manda um usuário novo para a API fictícia:

$ curl -i -X POST -d '{"nome":"Novo"}' https://api.exemplo.com/usuarios
HTTP/2 200
content-type: application/json
content-length: 87

[{"id":1,"nome":"Ana"},{"id":2,"nome":"Beto"},{"id":3,"nome":"Carla"}]

O -X POST muda o método e o -d '{…}' envia o corpo em JSON. A API devolveu a lista de usuários (no simulador, a resposta é fixa) com status 200.

Erro real: recurso que não existe (404)

404 Not Found 
$ curl -i http://exemplo.com/nao-existe
HTTP/1.1 404 Not Found
Server: nginx/1.25.3
Content-Type: text/html

<html><body><h1>404 Not Found</h1></body></html>

A conversa funcionou (o servidor respondeu), mas o recurso /nao-existe não existe lá — por isso o status 404. Repare que o corpo também traz uma página de erro.

Missão: digite curl -i http://exemplo.com/nao-existe e aperte Enter. A primeira linha da resposta deve ser HTTP/1.1 404 Not Found.

Erro real: nome que o DNS não acha

Could not resolve host 
$ curl site-que-nao-existe.com
curl: (6) Could not resolve host: site-que-nao-existe.com

Antes de qualquer conversa, o curl precisa traduzir o nome em IP. Se o DNS não conhece o nome, dá esse erro — a página "não abre" porque o nome não foi encontrado.

Resumo

  • curl [OPÇÕES] URL: faz a requisição HTTP e imprime a resposta.
  • -i cabeçalhos + corpo · -I só cabeçalhos · -v conversa inteira (Trying/Connected/GET) · -X POST -d '{…}' envia JSON · -o salva em arquivo.
  • Erros reais: curl: (6) Could not resolve host: (DNS) e 404 Not Found (recurso inexistente, mas a rede funcionou).
