Encapsulamento: pacote dentro de pacote

Lembra da carta internacional da aula de OSI? Cada camada colocava a carta dentro de um novo envelope. Em redes, chamamos isso de encapsulamento: os dados vão descendo as camadas e cada uma embrulha o pacote da camada de cima com o seu próprio cabeçalho — como uma carta dentro de um envelope, dentro de uma caixa, dentro do caminhão.

Você vai aprender
  • O que é encapsulamento e o que é o header (cabeçalho) de cada camada;
  • A ordem dos embrulhos: dados → segmento TCP → pacote IP → quadro Ethernet;
  • Quem é o "conteúdo" de cada embrulho (a unidade de dados de cada camada);
  • Como ver esses embrulhos na prática com tcpdump;
  • O processo inverso no destino: desencapsulamento.

A analogia das bonecas russas

Quando a Ana abre https://exemplo.com no navegador, acontece mais ou menos isso:

dados HTTP          →  "GET / HTTP/2" + resposta HTML
   ↓ embrulhado pelo TCP
segmento TCP        →  segmento + cabeçalho TCP (portas 443 → 54321, números de sequência…)
   ↓ embrulhado pelo IP
pacote IP           →  pacote + cabeçalho IP (192.168.1.50 → 93.184.216.34, TTL…)
   ↓ embrulhado pela Ethernet
quadro Ethernet     →  quadro + cabeçalho Ethernet (MAC aa:bb:cc:dd:ee:ff → MAC do roteador)

Cada "embrulho" é o header (cabeçalho) que a camada adiciona, com as informações que ela precisa: a camada TCP coloca as portas, a camada IP coloca os endereços IP, a Ethernet coloca os endereços MAC. No destino, o processo inverso — desencapsulamento — vai tirando um embrulho por vez, de baixo para cima, até sobrar só os dados HTTP.

Anatomia dos embrulhos

Dados (PDU da aplicação)
A mensagem HTTP de verdade: GET / HTTP/2 ou o HTML da resposta. Para a aplicação, é tudo o que existe.
Segmento (camada de transporte)
Dados + header TCP: porta de origem, porta de destino (443), número de sequência, flags (SYN/ACK…). É o TCP quem remontou tudo do outro lado, na ordem certa.
Pacote (camada de internet)
Segmento + header IP: IP de origem (192.168.1.50), IP de destino (93.184.216.34), TTL (time-to-live, o "prazo de validade" do pacote), protocolo (6 = TCP). É o IP quem roteia.
Quadro / frame (camada de acesso à rede)
Pacote + header Ethernet: MAC de origem (aa:bb:cc:dd:ee:ff) e MAC de destino (do gateway 192.168.1.1), além do trailer com a verificação de erro (FCS). É a placa de rede quem entrega no trecho local.

Vendo os embrulhos com tcpdump

O tcpdump captura os quadros que passam pela placa de rede — ou seja, você vê o pacote IP dentro do quadro Ethernet. No simulador, a saída mostra o IP de origem, o de destino e a porta (que está dentro do segmento TCP dentro do pacote IP):

Missão: rode tcpdump -i eth0 para "fotografar" os pacotes passando pela placa de rede da Ana e ver o encapsulamento na prática. Depois rode ping exemplo.com em outra caixa para gerar tráfego.

$ tcpdump -i eth0
tcpdump: listening on eth0, link-type EN10MB (Ethernet), snapshot length 262144 bytes
14:03:01.123456 IP 192.168.1.50.54321 > 93.184.216.34.443: Flags [S], seq 1234567, win 64240, length 0
14:03:01.145678 IP 93.184.216.34.443 > 192.168.1.50.54321: Flags [S.], seq 7654321, ack 1234568, win 64240, length 0

Na linha acima: 192.168.1.50.54321 > 93.184.216.34.443 — o IP (camada internet) e as portas (camada transporte, dentro do segmento TCP) aparecem juntos, porque o tcpdump lê o quadro e mostra o que está encapsulado dentro dele. A aula tcpdump aprofunda os filtros.

TTL: o prazo de validade do pacote

Todo pacote IP nasce com um TTL (ex.: 64). Cada roteador que passa desconta 1; se chegar a 0, o pacote é descartado e o roteador avisa com ICMP "Time Exceeded". Isso evita que pacotes fiquem circulando para sempre num loop de rotas — e é exatamente o truque que o traceroute usa (aula ICMP).

Resumo

  • Encapsulamento = cada camada embrulha os dados da camada de cima com seu próprio header, descendo; no destino, desembrulha subindo.
  • A ordem: dados → segmento TCP → pacote IP → quadro Ethernet (cada um dentro do anterior).
  • Header TCP = portas; header IP = IPs + TTL; header Ethernet = MACs. Cada camada só lê o seu embrulho.
  • O tcpdump mostra o pacote IP dentro do quadro Ethernet — o encapsulamento visível.
