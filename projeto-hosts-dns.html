Projeto 3 — DNS local: /etc/hosts + dig

O DNS é a agenda telefônica da internet: traduz nomes em IPs. Mas e se você quiser um apelido que só funciona no seu computador — sem registrar domínio nenhum? Aí entra o /etc/hosts: um caderno de apelidos local, que o sistema consulta antes de ligar para o DNS. É perfeito para testar um site antes de ele ir para o ar.

Você vai aprender
  • O que é o /etc/hosts e a ordem de consulta: hosts local primeiro, DNS depois.
  • A adicionar um apelido: 192.168.1.60 meusite.local.
  • A confirmar com dig meusite.local +short → 192.168.1.60, nslookup e ping.
  • Quem são os servidores DNS da máquina: cat /etc/resolv.conf.

Passo 1 — ver o caderno de apelidos atual

O arquivo /etc/hosts tem linhas no formato IP nome1 nome2…. Na máquina da Ana ele já traz o básico:

$ cat /etc/hosts
127.0.0.1   localhost
127.0.1.1   notebook
192.168.1.50 notebook
192.168.1.1  roteador gateway

Missão: rode cat /etc/hosts e veja os apelidos que já existem (repare no 192.168.1.1 roteador gateway).

Passo 2 — adicionar o apelido do projeto

A Ana tem um servidorzinho em 192.168.1.60 na rede dela e quer chamá-lo de meusite.local. Basta anexar uma linha no arquivo (na máquina real precisa de sudo, porque o arquivo é do sistema):

$ echo "192.168.1.60   meusite.local" | sudo tee -a /etc/hosts
192.168.1.60   meusite.local
/etc/hosts
127.0.0.1   localhost
127.0.1.1   notebook
192.168.1.50 notebook
192.168.1.1  roteador gateway
192.168.1.60   meusite.local     « a linha nova

Agora meusite.local vale 192.168.1.60 nesta máquina só — nenhum servidor DNS do mundo conhece esse nome. No simulador, o apelido já está cadastrado na tabela DNS fictícia; é por isso que o dig abaixo já responde.

Passo 3 — confirmar que o apelido resolve

$ dig meusite.local +short
192.168.1.60
$ nslookup meusite.local
Server:         192.168.1.1
Address:        192.168.1.1#53

Non-authoritative answer:
Name:   meusite.local
Address: 192.168.1.60
$ ping -c 2 meusite.local
PING meusite.local (192.168.1.60) 56(84) bytes of data.
64 bytes from 192.168.1.60: icmp_seq=1 ttl=64 time=2.31 ms
64 bytes from 192.168.1.60: icmp_seq=2 ttl=64 time=1.98 ms

Funcionou: o nome foi traduzido para o IP antes de qualquer consulta ao DNS externo — dá para provar tirando o cabo de rede: o ping meusite.local continua funcionando, porque a resposta está no /etc/hosts local.

Missão: rode dig meusite.local +short e confirme que o apelido responde 192.168.1.60.

Missão extra: rode ping meusite.local — repare que o próprio ping mostra o IP entre parênteses: PING meusite.local (192.168.1.60).

Passo 4 — quem são os servidores DNS desta máquina?

Quando o nome não está no /etc/hosts, o sistema pergunta aos servidores listados no /etc/resolv.conf:

$ cat /etc/resolv.conf
nameserver 192.168.1.1
nameserver 8.8.8.8
search localdomain

A máquina da Ana usa o roteador da casa (192.168.1.1, que o DHCP entregou) e o DNS público do Google (8.8.8.8) como reserva. O search localdomain completa nomes curtos com .localdomain.

Missão: rode cat /etc/resolv.conf e ache os dois servidores DNS configurados.

Detalhe real: em sistemas modernos (systemd-resolved), o /etc/resolv.conf pode ser um arquivo gerado — a edição manual vai para /etc/systemd/resolved.conf. E editar o /etc/hosts exige sudo. A ordem de consulta continua a mesma: hosts local primeiro, DNS depois (aula arquivo hosts aprofunda).

Resumo do projeto

  • /etc/hosts = apelidos locais de IP; consultado antes do DNS.
  • Formato: IP nome — ex.: 192.168.1.60 meusite.local.
  • Confirme com dig meusite.local +short → 192.168.1.60 e ping meusite.local.
  • Os servidores DNS da máquina estão em /etc/resolv.conf (nameserver …).
