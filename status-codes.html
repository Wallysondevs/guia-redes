Códigos de status — o carimbo da resposta

Depois que o cliente manda a requisição (com seu método e seus headers), o servidor responde começando por uma linha de status de 3 dígitos. Pense nela como o carimbo do correio dizendo o que aconteceu com a sua carta: "entregue", "mudou de endereço", "destinatário não existe", "problema no remetente".

Você vai aprender
  • A ler a linha de status: HTTP/1.1 404 Not Found.
  • As 5 classes: 1xx, 2xx, 3xx, 4xx e 5xx — e os códigos mais comuns de cada uma.
  • A diferença entre 404 e 500, e entre 401 e 403.
  • Ver os códigos na prática com curl -i no simulador.

A linha de status

HTTP/1.1 404 Not Found
HTTP/1.1
A versão do protocolo usada na resposta.
404
O código numérico — a máquina lê isso.
Not Found
A frase (reason phrase) — o humano lê isso.

As cinco classes

O primeiro dígito diz a classe do resultado:

ClasseSignificadoCódigos comuns
1xxInformação — "continue, estou processando".100 Continue
2xxSucesso — deu tudo certo.200 OK, 201 Created, 204 No Content
3xxRedirecionamento — o recurso mora em outro endereço agora.301 Moved Permanently, 302 Found, 304 Not Modified
4xxErro do cliente — a culpa é da requisição.400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 429 Too Many Requests
5xxErro do servidor — a culpa é do servidor.500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable

Na prática, no simulador

A máquina da Ana acessa sites fictícios. Veja três respostas diferentes:

$ curl -i http://exemplo.com
HTTP/1.1 200 OK
Server: nginx/1.25.3
Content-Type: text/html; charset=UTF-8

<html>...<h1>Exemplo.com</h1>...</html>
$ curl -i http://exemplo.com/nao-existe
HTTP/1.1 404 Not Found
Server: nginx/1.25.3
Content-Type: text/html

<html><body><h1>404 Not Found</h1></body></html>
$ curl -i https://api.exemplo.com/usuarios/999
HTTP/2 404
content-type: application/json

{"erro":"usuário não encontrado"}
  • 200 OK — a página existe e veio.
  • 404 Not Found — o servidor Procurou e não achou esse caminho (/nao-existe, ou o usuário 999). A URL estava certa, o recurso é que não existe.
  • Note que a API devolve o 404 em JSON ({"erro":"usuário não encontrado"}) — porque o cliente pediu JSON.

Missão: provoque um 200 OK: curl -i http://exemplo.com

Missão: provoque um 404 pedindo uma página que não existe: curl -i http://exemplo.com/nao-existe

Missão: veja o 404 em JSON da API: curl -i https://api.exemplo.com/usuarios/999

Leia direito os erros:
  • 404 = "não achei esse endereço" — a culpa é de quem pediu (URL errada ou recurso apagado).
  • 500 = "quebrei aqui dentro" — a culpa é do servidor (bug, banco fora do ar).
  • 401 Unauthorized = você não provou quem é (faltou login). 403 Forbidden = você provou, mas não tem permissão.
  • 429 = você fez requisições demais em pouco tempo (rate limit) — espere um pouco.

Resumo

  • A resposta começa com HTTP/x.y CÓDIGO frase — 3 dígitos dizem o resultado.
  • 2xx deu certo (200 OK, 201 Created); 3xx redirecionou (301, 302, 304); 4xx erro seu (400, 401, 403, 404, 429); 5xx erro do servidor (500, 502, 503); 1xx é só informes.
  • 404 = recurso não existe; 500 = servidor quebrou; 401 = faltou login; 403 = sem permissão.
  • Veja qualquer código na hora com curl -i URL.
