tcpdump: capturar pacotes no terminal

Até agora vimos comandos que fazem algo na rede (ping, curl, dig). O tcpdump faz o contrário: ele escuta. Ele coloca a placa de rede em modo promíscuo — que passa a receber todos os pacotes que passam pelo cabo, não só os endereçados a ela — e imprime cada um na tela. Pense nele como um grampo na linha telefônica (só em linhas suas, com permissão!): você ouve tudo que entra e sai da máquina.

Você vai aprender
  • A sintaxe: tcpdump -i eth0 [filtro] — e que no início aparece tcpdump: listening on eth0….
  • Os filtros BPF: host, port, tcp, udp, icmp, com and/or.
  • A anatomia de uma linha capturada: hora, origem.porta > destino.porta, flags, seq, length.
  • Parar com Ctrl+C e gravar em arquivo .pcap com -w (para abrir no Wireshark).

Capturando tudo na eth0

$ tcpdump -i eth0
tcpdump: listening on eth0, link-type EN10MB (Ethernet), snapshot length 262144 bytes
10:15:01.100001 IP 192.168.1.50.54321 > 93.184.216.34.80: Flags [S], seq 1548213, win 64240, length 0
10:15:01.123456 IP 93.184.216.34.80 > 192.168.1.50.54321: Flags [S.], seq 9921045, ack 1548214, win 65535, length 0
10:15:01.123500 IP 192.168.1.50.54321 > 93.184.216.34.80: Flags [.], ack 9921046, win 64240, length 0
10:15:01.201010 IP 192.168.1.50.51234 > 192.168.1.1.53: 12345+ A? exemplo.com. (29)
10:15:01.230044 IP 192.168.1.1.53 > 192.168.1.50.51234: 12345 1/0/0 A 93.184.216.34 (45)

Repare que dá para ver a vida toda da máquina: o handshake TCP (Flags [S], [S.], [.] — aula handshake) e até a consulta DNS em UDP porta 53.

Anatomia de uma linha de pacote

10:15:01.100001
Hora exata da captura (com microssegundos).
IP
O protocolo da camada de rede (IPv4).
192.168.1.50.54321 > 93.184.216.34.80
Origem IP.porta > destino IP.porta — o socket de cada lado da conversa.
Flags [S]
Flags do TCP (SYN, ACK, FIN… — tabela na aula de handshake).
seq 1548213, ack…, win 64240
Número de sequência, confirmação e tamanho da janela de recepción.
length 0
Tamanho dos dados úteis do pacote (0 = pacote de controle, só flags).

Filtrando: só o que interessa (BPF)

Capturar tudo gera muito barulho. Os filtros (BPF) selecionam na hora:

FiltroMostra só pacotes…Exemplo
host exemplo.comde ou para aquele host/IPtcpdump -i eth0 host exemplo.com
port 443com origem ou destino na porta 443tcpdump -i eth0 port 443
tcp / udp / icmpdo protocolo de transporte/rede indicadotcpdump -i eth0 udp port 53 (só DNS)
src 192.168.1.50 só de origem neste IPtcpdump -i eth0 src 192.168.1.50
combinadosand, or, nottcpdump -i eth0 host exemplo.com and port 443
$ tcpdump -i eth0 host exemplo.com and port 443
tcpdump: listening on eth0, link-type EN10MB (Ethernet), snapshot length 262144 bytes
10:20:11.500001 IP 192.168.1.50.55001 > 93.184.216.34.443: Flags [S], seq 2233001, win 64240, length 0
…

Missão: rode tcpdump -i eth0 e veja a linha tcpdump: listening on eth0… — a placa entrou em modo promíscuo e está capturando. (No simulador, Ctrl+C limpa a tela como no terminal real.)

Missão: rode tcpdump host exemplo.com — o filtro mostra só pacotes de/para o exemplo.com, e as linhas de pacote exibem o IP 93.184.216.34 do servidor.

Cuidados com o tcpdump
  • Normalmente precisa de root (sudo tcpdump …) para modo promíscuo.
  • Pare com Ctrl+C; no fim ele imprime um resumo ("N packets captured, N received by filter, N dropped by kernel").
  • Em produção, a captura pode conter dados sensíveis (senhas trafegam criptografadas em HTTPS, mas nem tudo é criptografado) — capture só o necessário e apague depois.
  • Para analisar depois (ou no Wireshark), grave em arquivo: tcpdump -i eth0 -w captura.pcap — o .pcap é o formato padrão de captura.

Resumo

  • tcpdump -i eth0 captura tudo que passa na placa (modo promíscuo) e imprime tcpdump: listening on eth0….
  • Filtros BPF: host, port, src, tcp/udp/icmp, combinados com and/or.
  • Cada linha mostra hora, origem.porta > destino.porta, flags, seq e length.
  • Ctrl+C para parar; -w arquivo.pcap grava para abrir no Wireshark.
