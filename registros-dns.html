Registros DNS — os campos da agenda

Um domínio não tem só um número de telefone: a agenda dele tem vários campos. No DNS, cada campo é um tipo de registro. Pense na agenda de um contato: telefone fixo (A), celular novo (AAAA), apelido (CNAME), e-mail (MX), recado no rodapé (TXT).

Você vai aprender
  • Os principais tipos de registro: A, AAAA, CNAME, MX, TXT, NS, SOA, PTR.
  • Consultar um tipo específico: dig exemplo.com MX.
  • Descobrir os servidores autoritativos (NS) de um domínio com whois.
  • As pegadinhas: CNAME não pode existir no domínio raiz; TXT é usado para provar posse do domínio.

Os principais tipos de registro

TipoO que guardaExemplo
AO endereço IPv4 de um nome.exemplo.com → 93.184.216.34
AAAAO endereço IPv6 de um nome.exemplo.com → 2606:2800:220:1:…
CNAMEUm apelido: aponta para outro nome.www.exemplo.com → exemplo.com
MXO servidor de e-mail do domínio, com prioridade (número menor = tenta primeiro).exemplo.com → 10 mail.exemplo.com
TXTTexto livre — SPF de e-mail, DKIM, ou prova de que você é o dono do domínio."v=spf1 include:_spf.exemplo.com ~all"
NSQuais servidores são autoritativos pelo domínio.exemplo.com → ns1.exemplo.com
SOADados administrativos da zona: contato do responsável, serial, tempos de cache.início da zona exemplo.com
PTRO reverso: de IP para nome.93.184.216.34 → exemplo.com

Consultando um tipo específico

O dig aceita o tipo como segundo argumento. No simulador, a resposta mostra o tipo pedido na QUESTION e na ANSWER:

$ dig exemplo.com A
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 4821
;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1

;; QUESTION SECTION:
;exemplo.com.           IN      A

;; ANSWER SECTION:
exemplo.com.            3600    IN      A       93.184.216.34

;; Query time: 12 msec
;; SERVER: 192.168.1.1#53(192.168.1.1)
$ dig exemplo.com MX
;; QUESTION SECTION:
;exemplo.com.           IN      MX

;; ANSWER SECTION:
exemplo.com.            3600    IN      MX      93.184.216.34

;; SERVER: 192.168.1.1#53(192.168.1.1)

Num servidor DNS real, cada tipo traz o seu dado próprio (o MX mostra o servidor de e-mail e a prioridade; o TXT, o texto; e por aí vai).

Missão: pegue o registro A (o IP) de exemplo.com: dig exemplo.com +short

Missão: consulte o registro de e-mail do domínio: dig exemplo.com MX — ache o tipo MX na resposta

Descobrindo os NS com whois

O whois consulta o registro do domínio (quem registrou, quando, e quais são os servidores de nome):

$ whois exemplo.com
Domain Name: EXEMPLO.COM
Registry: Verisign
Creation Date: 1995-08-14
Name Server: NS1.EXEMPLO.COM

A linha Name Server mostra o registro NS: é para esse servidor que o resolver manda a pergunta final (aula DNS a fundo).

Missão: descubra os servidores de nome do domínio: whois exemplo.com

Missão: compare com o nslookup, que traz a mesma resposta em formato mais simples: nslookup exemplo.com

Duas pegadinhas importantes:
  • CNAME não pode existir no domínio raiz — você não pode fazer exemplo.com apontar para outro nome; só subdomínios (como www.exemplo.com) aceitam CNAME.
  • TXT é muito usado para provar que você é o dono do domínio: Google, Microsoft e outros pedem um registro TXT específico antes de liberar um serviço.

Qual tipo de registro guarda o servidor de e-mail de um domínio?

Resumo

  • Cada tipo de registro é um campo da agenda do domínio: A/AAAA (IPs), CNAME (apelido), MX (e-mail), TXT (texto/verificação), NS (autoritativos), SOA (admin), PTR (reverso).
  • Consulte com dig HOST TIPO (ex.: dig exemplo.com MX) e dig HOST +short para só o valor.
  • whois exemplo.com mostra os Name Server (registros NS) e a data de criação do domínio.
