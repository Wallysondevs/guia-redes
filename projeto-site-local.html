Projeto 1 — site local com http.server + curl

Toda vez que você abre um site, algum computador está servindo arquivos por HTTP numa porta. Neste projeto a Ana vai fazer isso no próprio notebook: criar uma pasta com um index.html, ligar um servidor HTTP na porta 8000 e acessar o site com curl — primeiro "de dentro" (localhost), como se fosse um convidado batendo na porta dos fundos.

Você vai aprender
  • Que servir um site = um programa escutando numa porta (aqui, a 8000) e devolvendo arquivos.
  • O comando python3 -m http.server 8000 e por que ele "prende" o terminal.
  • A diferença entre curl localhost:8000 (só corpo) e curl -i localhost:8000 (headers + corpo, com 200 OK).
  • A confirmar a porta aberta com ss -tlnp (procure LISTEN na 8000).
  • O erro real Address already in use quando a porta já está ocupada.

Passo 1 — criar o site

Pense numa página web como numa Cartaz na porta de casa: o arquivo index.html é o cartaz, e a pasta onde ele mora é a casa. Crie a pasta e o arquivo:

$ mkdir ~/meu-site && cd ~/meu-site
$ cat > index.html << 'EOF'
<html><body><h1>Oi! Sou o site da Ana.</h1></body></html>
EOF
~/meu-site/
└── index.html      « a página que o servidor vai entregar

Passo 2 — ligar o servidor na porta 8000

O comando python3 -m http.server 8000 liga um servidor HTTP mínimo que entrega os arquivos da pasta atual na porta 8000. Repare: o terminal fica preso (o servidor fica rodando em primeiro plano). Para desligar, Ctrl+C; para rodar "soltinho" e liberar o terminal, rode em outra aba ou com & no fim.

$ cd ~/meu-site
$ python3 -m http.server 8000
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...

Na máquina fictícia do simulador esse servidor já está no ar (é o serviço python3 http.server que aparece no ss). Na sua máquina real, ligue você mesmo com o comando acima.

Missão: rode ss -tlnp no terminal e encontre a porta 8000 em estado LISTEN (ouvindo), junto com o processo python3.

$ ss -tlnp
Netid State  Recv-Q Send-Q Local Address:Port  Peer Address:Port Process
TCP   LISTEN 0      128    0.0.0.0:22           0.0.0.0:*     users:(("sshd",1012))
TCP   LISTEN 0      128    0.0.0.0:8000         0.0.0.0:*     users:(("python3",2031))

Passo 3 — acessar com curl (e ver o 200 OK)

Abra outro terminal e peça a página com curl. Sem opções, o curl imprime só o corpo da resposta; com -i, ele imprime também os headers — e a primeira linha é o status: HTTP/1.1 200 OK (o servidor achou o arquivo e está entregando).

$ curl localhost:8000
<html><body><h1>Oi! Sou o site da Ana.</h1></body></html>
$ curl -i localhost:8000
HTTP/1.1 200 OK
Server: SimpleHTTP/0.6 Python/3.12.3
Content-Type: text/html
Content-Length: 58

<html><body><h1>Oi! Sou o site da Ana.</h1></body></html>

O localhost (ou 127.0.0.1) é o endereço que aponta para a própria máquina — é o "eu mesmo" dos endereços IP. A porta 8000 é a porta da casa onde o servidor está ouvindo.

Missão: rode curl -i localhost:8000 no terminal e veja o 200 OK na primeira linha da resposta.

Missão extra: na mesma saída, procure o header Server: — ele diz quem atendeu o pedido (na máquina real apareceria SimpleHTTP/... Python/...).

Passo 4 — e no navegador?

Numa máquina real, basta abrir http://localhost:8000 no navegador — ele faz o mesmo GET que o curl fez e renderiza o HTML. Se outra pessoa da mesma rede quiser ver, acesse pelo IP da máquina: http://192.168.1.50:8000 (desde que o firewall não bloqueie a 8000 — aula de firewall).

Erro real: porta já em uso 
$ python3 -m http.server 8000
Traceback (most recent call last):
  ...
OSError: [Errno 98] Address already in use

Causa: já existe um servidor na porta 8000 (o seu mesmo, de outro terminal, ou outro programa). Solução: veja quem está com a porta com ss -tlnp, mate o processo antigo (Ctrl+C no terminal dele) ou escolha outra porta: python3 -m http.server 8001. A página Problemas comuns lista esse e outros erros.

Resumo do projeto

  • Servir um site local = rodar um servidor HTTP numa porta: python3 -m http.server 8000.
  • curl localhost:8000 traz só o corpo; curl -i localhost:8000 traz HTTP/1.1 200 OK + headers + corpo.
  • ss -tlnp mostra a porta 8000 em LISTEN, com o processo que está ouvindo.
  • Porta ocupada dá Address already in use — troque de porta ou mate o processo antigo.
